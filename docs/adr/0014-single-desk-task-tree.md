# ADR 0014. 대화는 따까리 하나, 일은 트리, 지난 일은 서고

- 상태: 채택(첫 구현) (2026-10-13)
- 결정자: 사용자("채팅이든 회사 업무든 ChatGPT·Claude 웹 같은 세션 목록 디자인을 할 이유가 없어졌다", "무조건 하나의 채팅창", "루트도 여러 개, 가지도 많고 계층도 계속 내려가는 트리", "현재 작업 중인 것 위주로 보이고, 과거 작업은 도서관처럼 모았다가 다시 조회·검색", "창은 하나, 상단에서 개인/회사 전환")

## 문제
ADR 0013 으로 사용자가 말하는 곳(접수)과 일하는 곳(기획·작업 세션)이 갈렸다. 그런데 화면은 여전히 "새 세션"을 만들고 사이드바에 세션을 날짜별로 쌓는 대화 앱 모양이었다. 접수는 메시지마다 따로 돌고 엔진 대화를 이어 쓰지 않아, 대화창을 여러 개 둘 이유가 없다. 실제로 볼 것은 대화 목록이 아니라 접수 아래로 뻗은 일의 트리다.

## 결정

### 대화는 모드마다 하나
- `POST /api/desk {pool}`: 그 모드(personal·work)의 보관되지 않은 접수 중 가장 최근 것을 돌려주고, 없으면 기본 워크스페이스에 만든다. 두 기기가 처음 동시에 열어도 하나만 생기게 pg advisory xact lock 을 건다.
- 제목은 `따까리` / `따까리 · 회사`로 고정한다. "새 작업"이 아니므로 첫 메시지가 제목을 바꾸지 않는다.
- 접수 대화를 보관하면 다음에 열 때 빈 접수가 새로 생긴다(대화 비우고 새로 시작). 옛 접수는 서고에 남는다.
- 대화가 끝없이 길어지므로 `GET /sessions/{id}/runs?limit=&before=` 로 최근 것부터 읽는다. limit 이 없으면 전처럼 전부 준다.

### 트리
- 뿌리는 접수가 넘긴 기획 세션이다. 접수 자신은 뿌리가 아니라 그 위의 대화창이다. 부모가 없는 옛 세션(일반 대화·옛 메인 오케스트레이터·이전 접수)은 서고에서만 뿌리로 본다.
- 하위로는 `parent_id` 를 따라 몇 겹이든 내려간다(재귀 CTE). 접수 아래로는 내려가지 않는다(접수의 자식은 각자 뿌리).
- 노드 = 세션 + 마지막 Run 상태·프로필·모델 + 마지막으로 끝난 Run 결과 앞 200자. 세션 수와 상관없이 쿼리 두 번(DISTINCT ON)으로 붙인다.

| API | 무엇 |
|---|---|
| `GET /api/tasks/active?recent_hours=6` | 실행·대기 중인 세션이 있거나 최근 N시간 안에 움직인 뿌리의 트리 전체. 실행 중인 뿌리가 먼저 |
| `GET /api/tasks/library?pool=&before=&limit=` | 뿌리만 최근 순 + 하위 수·실행 중·실패 수. `next_before` 커서 |
| `GET /api/tasks/search?q=&pool=` | 제목·지시·결과 ILIKE. 세션마다 한 번, 제목 > 지시 > 결과 순으로 근거를 고르고 뿌리부터의 경로와 일치 부분 앞뒤를 준다 |
| `GET /api/tasks/{id}/tree` | 그 세션이 속한 뿌리의 트리 전체 + 뿌리부터 그 세션까지 경로 |

### 화면(front)
- 사이드바·모바일 드로어의 세션 목록을 지운다. 그 자리에 "진행 중"(일이 도는 뿌리), "최근 끝남"(6시간 안), 서고에서 연 옛 일이면 "지금 보는 일"을 트리로 보인다.
- 트리 안내선은 파일 트리(`.tk-tree`)와 같은 문법이다. 일이 도는 가지만 안내선이 에이전트 색(`agent.live`)이 되어, 접혀 있어도 어디서 일하는지 보인다. 상태는 모양으로도 다르다(실행 중 점, 대기 빈 점, 완료 체크, 실패 엑스, 취소 금지).
- `/chat`·`/work` 는 그 모드의 따까리 대화, 헤더의 세그먼트로 오간다. "새 세션"과 회사 업무 탭은 없앤다. `/chat/:id` 는 트리의 한 노드이고 헤더 메타에 뿌리부터의 경로를 링크로 둔다.
- `/tasks`(작업): 검색과 모드 필터, 진행 중 트리(모바일만, 데스크톱은 사이드바가 같은 것을 보여 준다), 날짜별(오늘·어제·이번 주·월) 서고. 서고 줄을 펼치면 그 자리에서 트리를 불러온다.

## 버린 것
- 메시지마다 개인/회사를 고르는 토글(한 대화에 두 모드 섞기): Run 에 pool 이 필요하고 접수 코드(desk.py)를 바꿔야 한다. 사용자가 "창은 하나, 상단에서 전환"을 골랐다.
- 트리를 프론트에서 세션 목록을 재귀로 불러 세우기: 깊이만큼 요청이 늘고, 활성 판단이 하위 전체에 걸려 서버에서 한 번에 하는 편이 맞다.
- ARIA tree(화살표 키 탐색): 행마다 링크와 펼침 버튼이 따로 있어 공개(disclosure) 패턴이 Tab 만으로 다 닿는다.
- 전문 검색 색인(pg_trgm GIN·tsvector): 개인 규모라 ILIKE 로 시작한다. 느려지면 색인을 단다.

## 알려진 한계
- "최근 끝남" 기준은 세션 `updated_at` 이다. 기획 세션은 작업 보고를 받을 때도 갱신되어 조금 더 오래 남는다.
- 검색은 Run 결과 전체를 ILIKE 로 훑는다. 결과가 수만 건이 되면 느려질 수 있다(확인 필요).
- 옛 접수(오늘 ADR 0013 이후 "새 대화"마다 생긴 것)는 서고에서 "따까리 대화" 줄로만 보인다. 그 아래 기획 세션은 각자 뿌리로 따로 보인다.
