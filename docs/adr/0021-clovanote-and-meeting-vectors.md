# ADR 0021. 클로바노트 연동(브라우저 어댑터·작업 큐·노트 DB)과 회의록 벡터 저장

> **대체됨/폐기(2026-10-15)**: 외부 전사 연동·설정·API·테이블 정책은 [ADR 0027](0027-retire-clovanote.md)로 대체했다. 아래는 당시 결정의 원문 기록이다. 회의록 본문·벡터 및 요청별 모델 수명 정책은 유지한다.

> 후속 결정: [ADR 0026](0026-local-first-meetings.md)이 기본 전사를 로컬로, 클로바 연동·자동 동기화를 기본 꺼짐으로 전환하고 E5 상주 모델을 요청별 자식 프로세스로 변경했다. 이 문서는 최초 연동의 기록이다.

- 상태: 채택 (2026-10-13)
- 결정자: 사용자. "클로바노트에 녹음 업로드하고 데이터 가져올 수 있게 + 이미 올라간 노트 가져오기", "처리 상태가 UI 로 보이게",
  "agent 가 도구로 쓸 수 있게 DB 화", "맥락 도서관에 벡터 DB 로도 저장", "개발한 방법을 주석으로 자세히".
- 잇는 것: ADR 0010(회의록, 클로바노트 자리만 있던 것을 채운다), ADR 0009(임베딩 없는 도서관에 회의록만 벡터를 더한다).

## 1. 클로바노트 연동

공개 API 가 없다. 전용 Chrome 프로필을 Playwright 로 창 없이 띄우고 웹 앱의 내부 REST API 를 같은 쿠키·세션 헤더로 부른다.
화면 클릭 자동화는 하지 않는다. 확인한 API·함정·로그인 방식의 정본은 `src/ttakkari/meetings/clovanote.py` 맨 위 주석이다. 요점:

| 결정 | 이유(2026-10-13 실제 계정으로 확인) |
|---|---|
| 평소 Chrome 프로필 대신 전용 프로필 `~/.ttakkari/clovanote-chrome` | Chrome 136+ 는 기본 사용자 폴더의 자동화 통로를 막고, macOS TCC 가 다른 앱의 Chrome 폴더 읽기를 막는다 |
| 로그인은 사람이 **일반 Chrome**(`open -na "Google Chrome" --args --user-data-dir=…`)에서 한 번 | Playwright 창에서 로그인하면 네이버가 자동화를 감지해 아이디 보호(본인인증)를 걸었다. 일반 창에선 추가 인증이 없었다 |
| '로그인 상태 유지' 필수, 감시가 영구 쿠키를 확인 | 체크하지 않으면 NID_AUT 가 세션 쿠키라 Chrome 을 닫으면 풀린다. 체크하면 약 1년짜리 영구 쿠키 |
| 자동화 Chrome 은 `--use-mock-keychain`·`--enable-automation` 을 빼고 띄운다 | mock 키체인으로 열면 실제 키체인으로 암호화된 쿠키를 못 풀고 **Chrome 이 지운다**(로그인 쿠키를 한 번 날렸다) |
| 세션 헤더(note-session-id 등)는 홈을 열어 앱 요청에서 가로챈다 | 쿠키만으론 400 "empty session id". 앱이 세션을 만들고 핑으로 살려 둔다 |
| 비밀번호는 저장하지 않는다 | 자동 입력은 봇 탐지를 더 부르고, 쿠키 세션으로 충분하다. 끊기면 화면의 '로그인 창 열기' 한 번 |

재로그인은 Mac 화면에 창을 띄우는 일이라 폰에서만 쓰는 중에는 할 수 없다(화면 공유로 대신한다). 일회용 번호 로그인은 자동화 창에서 입력해야 해서
위와 같은 봇 탐지를 부를 수 있어 넣지 않았다.

## 2. 작업 큐(`meetings/clova_jobs.py`)와 상태 표시

프로필 하나는 Chrome 하나만 열 수 있어 작업을 한 줄로 처리한다. `clovanote_jobs` 행이 단계(stage)·진행률·기록(steps)을 갖고 화면이 그대로 그린다.

| 종류 | 단계 | 결과 |
|---|---|---|
| sync | 연결 → 목록 → 전사 받기 → 완료 | 모든 노트 메타를 `clovanote_notes` 에 upsert, 바뀐 노트만 전사(화자·시각 구간)를 받는다. 30분마다 자동(`clovanote_poll_seconds`) |
| import | 연결 → 전사 받기 → 회의록 → 분석 요청 → 완료 | 노트 → 회의록(`transcript_source=provider:clovanote`, 참석자=화자) + 분석 Run |
| upload | 연결 → 노트 만들기 → 업로드 → 전사(0~100%) → 전사 받기 → 분석 요청 → 완료 | 회의록의 녹음을 클로바노트에 올리고 전사를 받아 `transcribed` 로 보낸 뒤 분석 |

- 업로드는 기존 Provider 인터페이스(ADR 0010)를 그대로 쓴다. `submit` 이 upload 작업을 넣고 작업 id 를 돌려주며, `poll` 은 작업 행을 읽는다.
- 서버가 재시작하면 running 작업은 queued 로 돌아가 이어진다. 업로드는 이미 올린 노트가 있으면 전사 대기부터 한다.
- 로그인 창이 열려 있으면 작업은 기다렸다 다시 시도한다(Busy).
- `POST /api/meetings {auto_process: true}`: 녹음이면 곧바로 전사 요청 → 전사 끝나면 분석, 전사 텍스트면 곧바로 분석. 막히면 회의는 만들고 `auto_error` 로 사유.

## 3. 노트 DB 와 에이전트 도구

`clovanote_notes` 가 에이전트가 읽는 정본이다(제목·녹음 시각·길이·화자·상태·전사·화자/시각 구간·클로바 요약·가져온 회의 id).
클로바노트 계정은 개인 계정이므로 회사 세션은 회사 회의로 가져온 노트만 보고, 동기화를 걸 수 없다.

MCP(모든 Run): `list_clovanote_notes`·`get_clovanote_note`(구간을 페이지로)·`search_meetings`(읽기 전용, 자동 승인),
`sync_clovanote`·`import_clovanote_note`(쓰기). 가져오기는 회의록을 만들고 분석할 뿐이며 맥락 도서관 반영은 여전히 사용자 승인(ADR 0010)이다.

## 4. 회의록 벡터 저장(`meetings/vectors.py`)

ADR 0009 는 외부 임베딩 모델 없이 키워드 검색만 썼다. 사용자가 회의록을 벡터로도 저장하길 원해 **회의록에 한해** 로컬
`intfloat/multilingual-e5-large`(fastembed, 1024차원, ~/.ttakkari/models 에 이미 있던 모델)를 다시 쓴다. 기존 기억·문서는 그대로 어휘 검색이다.

- 회의 한 건을 요약·결정·액션·미해결·논의·전사 구간(700자, 120자 겹침, 줄 경계 유지)으로 잘라 `meeting_chunks` 에 둔다.
  조각마다 "[회의 날짜 '제목' · 프로젝트]" 를 앞에 붙여 검색 결과만 봐도 출처를 안다. 범위·프로젝트를 조각에 복사해 검색 범위 규칙(ADR 0009)을 지킨다.
- 전사 저장·분석 완료·프로젝트 변경·항목 수정·액션 변경 승인 뒤 다시 만든다(디바운스, 한 트랜잭션 교체). 시작 시 `pending`·`none` 을 다시 색인한다.
  상태는 `meetings.vector_status`(none|pending|ready|failed)·`vector_chunks` 로 화면에 보인다.
- 검색: ADR 0009 어휘 점수 + `max(0, 유사도 − 0.78) × 8`. e5 는 무관한 문장도 0.76 안팎이라 바닥값을 뺀다(10-13 실측: 관련 0.81~0.84, 무관 0.76).
  벡터로만 걸린 조각은 0.80 이상만. 회의당 최대 3조각. 정리된 항목이 전사 구간보다 약간 앞선다.
- `recall` 의 기본 종류에 `meeting` 이 들어가 에이전트가 따로 부르지 않아도 회의 내용이 걸린다. HNSW 코사인 인덱스.
- 테스트·모델 없는 환경은 `TTAKKARI_CONTEXT_EMBEDDER=hash`, 끄려면 `off`(어휘 검색만).
- 비용: 모델 로드 3~25초(첫 사용 때), 메모리 약 2GB. 한 시간 회의(전사 약 3만 자)는 조각 약 50개.

## 버린 것

- 네이버 비밀번호 저장·자동 입력: 봇 탐지와 계정 보호를 부른다.
- 화면 클릭으로 업로드: 앱의 업로드 상태(draft)가 숨은 파일 입력만으로는 안 생겨 실패했다. 내부 API 가 더 안정적이다.
- 별도 벡터 DB: ADR 0007 과 같은 이유로 pgvector 하나로 충분하다.

## 검증

가짜 클라이언트로 동기화(바뀐 노트만 전사 받기)·가져오기(분석까지·중복 거절)·업로드(진행률 기록·자동 분석)·형식 거절·로그인 필요·재시작 이어하기,
조각화·임베딩·recall/의미 검색의 범위 규칙을 테스트한다(`tests/test_clovanote.py`). 실제 계정으로 상태 확인(2.7초)·목록·전사 수신·업로드 →
전사 완료(8초 음성 4초)·휴지통 이동을 어댑터로 확인했다.
