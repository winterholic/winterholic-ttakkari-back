# ADR 0026. 로컬 우선 회의 전사와 요청별 모델 프로세스

> **대체됨/폐기(2026-10-15)**: 외부 전사 연동·설정·API·테이블 정책은 [ADR 0027](0027-retire-clovanote.md)로 대체했다. 아래는 당시 결정의 원문 기록이다. 회의록 본문·벡터 및 요청별 모델 수명 정책은 유지한다.

- 상태: 구현, 운영 미배포(2026-10-15).
- 사용자 결정: 클로바노트 의존에서 벗어나고 모델은 필요할 때만 로드해 평시 컴퓨터 부하를 줄인다.
- ADR 0025의 기본 전사·큐 정책과 ADR 0021의 E5 수명을 갱신한다.

기본 Provider는 설정 `meeting_default_provider=local_whisper`로 결정한다. 로컬 기능은 기본 켜짐이지만 가중치 경로와 실행 환경을 검증해야 ready다. 준비되지 않으면 사유를 표시하고 녹음을 보존한다. 클로바노트로 자동 우회하지 않는다. 기존 클로바 데이터·명시 전사·가져오기 기능은 유지하며 연동과 자동 동기화의 새 기본값은 false/0이다. 기존 환경의 명시 설정값은 그대로 우선하므로 운영 전환 시 배포 담당자가 확인한다.

회의 목록은 클로바 연결 조회를 하지 않는다. 해당 탭·엔진을 명시 선택한 동안에만 조회·안내한다. 전사 엔진 API는 default_provider/is_default를 제공한다. 상세 화면은 현재 Provider에 해당하는 진행만 표시한다.

Whisper/선택 화자·분리 모델은 이전과 같이 자식 프로세스 안에서만 존재한다. E5도 같은 프로세스 감독기를 이용해 질의·색인 요청마다 로드하고 종료한다. 모델이 없는 부모는 직렬 요청과 제한시간·종료·회수를 관리한다. E5 CPU 스레드는 기본 2, 제한시간은 기본 300초다. 요청 중 모델 다운로드와 암묵 HF 인증은 금지한다. 기존 모델 파일 캐시와 벡터는 보존하며 새 의존성은 추가하지 않는다. E5의 모델 명칭·query/passage 접두사·정규화·벡터 차원은 유지한다.

STT 큐는 시작 복구 후 이벤트를 기다린다. 새 job은 기존처럼 별도 트랜잭션으로 저장하되, 회의의 provider_job_id 커밋 후에만 API가 큐를 깨운다. 구간 후보 API도 커밋 후 깨운다. 빈 큐의 매초 조회를 제거하고, DB 오류 재시도 대기는 유지한다. 비활성 클로바 큐는 시작 시 DB·브라우저 작업을 만들지 않는다.

정확도·화자/중첩 채택 정책과 원본 보존은 변경하지 않는다. 분석은 설정된 외부 AI 서비스를 사용할 수 있다. 요청마다 E5를 로드하는 시작 비용은 받아들이며 실제 장기 운영의 RSS 절감량은 배포 후 별도 관찰한다.

근거와 검증 범위는 [요청 수명 검증 기록](../stt/local-first-2026-10-15.md)에 있다. 운영 재시작·배포는 이 작업에서 하지 않는다.
