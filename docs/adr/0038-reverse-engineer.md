# ADR 0038: 리버스 엔지니어링(저장소 뜯어보기)

> 2026-10-18 수정: GitHub 저장소 요약을 사용자 요구로 간주한 전제를 폐기했다. 신규 요청의 정본은 [ADR 0041](0041-reverse-reconstruction.md)이며, 이 문서는 이전 기록의 구현 이력이다.

- 상태: 구현(2026-10-18). 사용자 요청("화제의 rea를 나도 해보고 싶다")에 따른 에이전트의 구현 설계이며 별도 사용자 승인 기록을 뜻하지 않는다.
- 당시 구현 전제(사용자 요구를 잘못 해석): GitHub URL·로컬 경로를 주면 따까리가 저장소를 뜯어보고 정리 결과를 보여준다. 결과뿐 아니라 요청 → 수집 → 구조 파악 → 핵심 흐름 → 정리·요약의 전 과정이 단계별로 기록되고 페이지에서 보인다.

## rea에서 차용한 점

rea(morluto/rea)는 "에이전트가 목표물을 뜯어보고 증거와 함께 설명한다"는 MCP+CLI+절차 문서 조합이다. 따까리는 바이너리·런타임이 아니라 소스 저장소를 대상으로 삼으므로 아래만 차용한다.

- 증거 우선: 모든 결론에 관찰 근거를 붙이고, 모르는 범위는 한계로 명시한다. 확인 못한 내용은 '확인 필요'로 남긴다.
- 단계·산출물 구조: 빠른 시작 → 동작 원리 → 대상별 안내의 순서를 결과 페이지(개요 → 아키텍처 → 모듈 → 흐름 → 차용 아이디어 → 한계) 타임라인에 그대로 쓴다.
- 정적 검사는 실행하지 않는다: rea의 정적 JS/.NET 검사가 파일을 읽기만 하듯, 대상 코드는 절대 실행하지 않는다(빌드·스크립트·테스트 금지).
- 차용하지 않은 것: 바이너리·APK·펌웨어·패킷 분석, Hopper/Ghidra/IDA 연동, 런타임 캡처, evidence bundle export. 필요해지면 별도 ADR.

## 결정

- 독립 모듈 `ttakkari/reverse.py`와 `api/reverse.py`(`/api/reverse/*`, `/api/agent/reverse/*`). 디자인시스템·아크크래프트 코드와 섞지 않는다.
- 단계는 request → collect → inventory → structure → flows → summarize 6개. 각 단계는 상태·시각·evidence[]·notes[]를 갖는다.
- 수집은 `git clone --depth 1`만 쓴다. 대상은 https Git URL(owner/repo 약칭은 github.com으로 정규화) 또는 존재하는 로컬 디렉터리다. `git@`·http·file·URL 자격 정보는 422로 거부한다.
- 비밀 파일(.env 등)은 읽지 않고 개수만 세며 이름도 결과에 싣지 않는다. `.git`·node_modules·가상환경·캐시는 걷지 않는다. dist/build/target은 1차 산출물이라 분석 대상에 둔다(걷기 5만 상한).
- import 추적은 파이썬·JS/TS 정적 정규식 기반이다. TS ESM의 `./x.js` → `x.ts` 대응을 푼다. 진입점 → 참조 허브 BFS, 못 닿으면 참조수 내림차순 탐사로 경로를 만든다. 동적 로딩·리플렉션은 한계로 남긴다.
- 차용 아이디어는 관찰된 특성에서만 만든다(MCP 규약·계약 문서·절차 문서·사례 문서·단계 안내·근거 명시). 근거 없는 제안은 넣지 않는다.
- 실행은 백엔드 프로세스의 백그라운드 asyncio 작업 + DB(`reverse_jobs`)다. 작업 세션(worker) 실행 인프라(에이전트 CLI Run)는 쓰지 않는다. 이유: 분석이 결정적 정적 검사라 모델 쿼터·대기 없이 끝나고 pytest로 검증할 수 있다. 기획 세션은 MCP 3종으로 대화에서 시작·조회한다.
- 소유자 API와 개인 세션 MCP가 같은 기록을 쓴다(디자인시스템 make_router 패턴). MCP는 `reverse_start`(쓰기, readOnly 아님·자동 승인 목록) + `reverse_list`·`reverse_get`(읽기 전용) 3종이다.
- DB 마이그레이션 `0041_reverse_jobs`(additive only). 진행 중 재시작은 조회 시 stale(30분)로 실패 표시한다. 동시 2개까지, 나머지는 queued로 대기한다.
- 프론트는 `/reverse`(목록·요청) + `/reverse/:jobId`(타임라인·결과). 진행 중 2.5~3초 폴링, features.ts에 넣어 더보기·부가 기능 모달에 같이 나온다. 토큰 준수·light/dark는 기존 tk 변수로 자동 대응한다.

## 결과·한계

- 새 테이블 1개·마이그레이션 1개. generation protocol 변경 없음.
- 한계: 런타임 동작·외부 연동은 읽지 못해 확인 필요로 남는다. 서버 재시작 시 진행 중 작업은 stale 실패가 된다. clone본 정리는 삭제 시에만 한다.
