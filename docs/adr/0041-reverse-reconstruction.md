# ADR 0041: 자연어 대상 설명 → 관찰·추론 → 작업공간 소스 재현

- 날짜: 2026-10-18
- 상태: 채택(사용자가 이번 대화에서 명시한 기능 방향)
- 대체: ADR 0038·0040의 신규 요청·실행 방식. 이전 저장소 분석 기록은 조회한다.

## 문제와 요청

사용자는 GitHub 주소를 입력해서 소스를 요약하는 기능이 아니라, 소스가 없는 대상의 동작을
채팅처럼 자연어로 자세히 설명하고, 따까리가 분석·검증해서 우리 작업공간에 소스로 작성하기를 요구했다.
`morluto/rea`는 참고 도구였다. 저장소 요약을 사용자의 요청으로 기록한 이전 ADR의 전제가 틀렸다.

## 실행 계약

- 신규 `POST /api/reverse`·MCP `reverse_start`는 description(40,000자), 선택 workspace_id를 받는다.
  설명 속 참고 URL·경로는 가능하다. 주소 한 개나 owner/repo만으로는 시작하지 않는다.
- `ReverseJob(kind=reconstruction)`은 작업공간, 구현 세션, 독립 검증 세션을 연결한다.
  소스는 `<workspace>/reverse-engineering/<job-id>/src/`, 테스트는 tests/, 실행법은 README.md이다.
- 새 CLI 호출기나 요약용 desk 경로를 쓰지 않는다. 기존 auto/general worker Run이 도구를 쓰고,
  계정풀·용량 선택·폴백·쿼터 대기·generation 소유권·재시작 재개를 그대로 따른다.
  회사 작업공간은 work 계정 범위로 실행한다.
- 작업자는 관찰과 가설을 구분하고 evidence/에 자료·로그를 남긴다.
  .reverse/<run-id>.progress.json의 observe/infer/implement 단계 기록을 표시한다.
  마지막에는 해당 Run ID의 .reverse/<run-id>.json에 소스 목록, 관찰 근거, 실제 실행 검사 기록을 저장한다.
- 서버는 비어 있지 않은 실제 소스·관찰 근거·성공 검사 로그를 확인한다. 문서만 있거나
  답변에 완료라고 적힌 것만으로 done이 되지 않는다. 이 확인은 의미적 동작 일치 증명이 아니다.
- 구현 기록이 유효하면 종료 트랜잭션에서 독립 auto/verification 세션을 한 번 큐에 넣는다.
  검증자는 원래 설명과 추가 지시, 실제 소스, 입력·출력과 경계·오류 사례를 실행 대조한다.
  별도 Run의 유효한 검사 기록과 passed 판정이 있어야 done이다.
  필수 검사는 모두 expected_exit_code(기본 0)에 맞아야 하며 성공 검사도 최소 하나 있어야 한다.
  기대된 오류 입력의 비정상 종료는 expected_exit_code로 표시한다. 선택적인 환경 진단 실패는
  required=false와 구체적인 reason을 함께 남길 때만 제외한다. 다른 검사 하나의 성공으로
  실패한 필수 검사를 덮지 않는다. verdict=failed의 실제 실패 로그도 보존하고 부분 완료로 처리한다.
  Flash/Muse 구현도 verification의 GPT/Claude 경로를 거치며 원래 Run의 verification_status에 결과를 기록한다.
- 대상 접근이나 정보가 부족하면 needs_input, 소스/검사 누락 또는 검증 불합격은 partial,
  실행 실패는 failed다. 쿼터 대기는 기존 Run 상태에서 waiting으로 표시한다.
- 후속 `POST /{id}/messages`·MCP reverse_message는 같은 폴더와 구현 대화를 이어가며
  추가 요구를 대상 설명에 보존한다. 진행 중에는 중지하거나 기다린 뒤 추가 설명한다.
- 내려받기 ZIP에는 선언한 소스·검사 로그와 README·tests만 담는다. 원본 실행물·비밀 파일은 제외한다.
  경로 탈출, 절대경로, symlink, 빈 파일, 민감 파일을 기록 결과로 인정하지 않는다.

## 화면과 기록

자연어 textarea, 선택 작업공간, 요청 목록, 과정 타임라인, 소스·검사·관찰 결과, 실행 대화·파일 탐색,
ZIP 다운로드, 후속 설명/수정 요청, 중지를 제공한다. 이전 저장소 분석은 `이전 분석 기록`으로 표시한다.
읽기용 legacy 정적 분석 함수와 회귀 테스트는 보존하지만 신규 API 입력으로 호출되지 않는다.

## 검증 범위와 한계

DB 통합 테스트는 실제 Run manager와 구현·검증 프로세스, 계정 선택, 소스 실행, ZIP 아티팩트 등록을
거친다. 모델은 결정적 테스트 실행물이다. 임의의 웹·앱·바이너리에 대한 상용 모델의 분석 품질을
보증하지 않는다. 실제 대상의 관찰 가능성과 도구 권한에 따라 후속 설명이 필요할 수 있다.
manifest와 단계 기록은 작업자의 보고이며, 서버의 파일 실재 확인과 별도 검증자의 동작 대조를 구분한다.
