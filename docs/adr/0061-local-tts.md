# ADR 0061. 로컬 TTS: 별도 페이지·엔진 추상화·요청별 프로세스 (초안)

- 상태: 초안(2026-10-20). 병행 벤치 세션의 Kokoro 측정 결과 반영 후 채택 판단.
- 선행: ADR 0025·0026·0027·0028(로컬 STT·요청 수명), ADR 0010(회의록), [TTS 설계](../design/local-tts.md).
- 사용자 결정: TTS는 회의록 STT에 통합하지 않는다. 별도 생성 페이지 + 채팅 응답의 선택적 재생 버튼. 엔진은 Kokoro-82M 우선·로컬·무료·교체 가능. 유휴 자원 점유 최소화.

## 결정

1. 별도 TTS 경로를 둔다. `src/ttakkari/tts/` 독립 패키지와 `/api/tts` 라우터, 프론트 `/tts` 페이지. 회의록 파이프라인·STT 큐·STT 스키마를 변경하지 않는다.
2. 엔진 추상화를 둔다. 부모 프로세스는 `TtsProvider` Protocol(voices·synthesize·capabilities·availability)만 본다. Kokoro 어댑터(워커 모듈·모델 경로·음성 목록·청크 권장값·출력 형식)는 플러그형으로 두고 벤치 결과로 확정한다.
3. Phase 1 프로세스 모델은 요청별 일회용 자식 프로세스다. `model_process.run_json_worker`를 재사용하며 STT와 같은 감독(회수·타임아웃·부모 감시·무자격증명·오프라인 강제)을 따른다. 유휴 타임아웃 상주는 쓰지 않는다.
4. 문장 청크 단위로 합성한다. 부모가 정규화·분할·캐시 조회를 하고 캐시 미스 청크만 워커 1회 호출로 합성한다. 진짜 바이트 스트리밍 대신 청크 완성 + 순차 재생으로 iOS 호환성을 확보한다.
5. 반복 음성을 캐싱한다. 키는 `blake2b("tts1" ‖ engine ‖ model_revision ‖ voice ‖ speed ‖ normalize(text))`이며 파일은 `<home>/tts-cache/`에 둔다. 입력 원문은 DB에 저장하지 않는다(해시만).
6. STT·E5와 모델 실행 슬롯(기본 2, CPU 스레드 STT 4 + TTS 2)을 공유한다. STT 장시간 작업이 TTS를 막지 않으면서 CPU 경합을 상한 안에 둔다.
7. `<audio>` 재생용 오디오는 단기 토큰 URL로 서빙한다. artifacts download-link 패턴을 따르며 tts 전용 토큰(TTL 10분)을 둔다.

## 상주를 택하지 않은 근거

유휴 자원 0 요구를 직접 충족하지 못하고(타임아웃 창 점유), 세대 교체 드레인·프리로드·헬스체크 복잡도가 필요하며, Kokoro 로드 비용 미확인 상태의 시기상조 최적화이기 때문이다. 캐시 미스 단문 TTFA p50이 8초(가설, 벤치로 확정)를 넘으면 유휴 타임아웃 상주 도입을 재검토한다. 전환해도 요청별 경로는 폴백으로 유지한다.

## 대안과 한계

- 회의록 STT 통합안: 사용자가 거부했다. TTS 생성(텍스트→음성)과 회의 전사(음성→텍스트)는 입력·출력·저장 수명이 달라 합치면 양쪽 스키마·큐가 오염된다.
- 바이트 스트리밍안: Phase 2 후보다. iOS `<audio>` 호환성과 캐시 결합이 청크 방식에서 단순하다.
- 상주 프로세스안: 위 전환 기준으로만 재검토한다.
- mp3 트랜스코딩: Phase 1 범위 밖이다. wav 용량 측정 후 판단한다.

## 검증 범위

채택 전에 다음이 필요하다. Kokoro 한국어 품질·권장 청크·출력 형식·로드 시간·메모리(병행 벤치 세션), TTFA 목표 확정, 오디오 토큰 방식 결정(§7 대안), Alembic 다음 번호 확인. 검증 기록은 `back/docs/tts/`에 둔다.
