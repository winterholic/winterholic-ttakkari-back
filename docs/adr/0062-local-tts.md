# ADR 0062. 로컬 TTS: 별도 페이지·엔진 추상화·요청별 프로세스 (개정)

- 상태: 검증대기 (2026-10-20, 독립 재검증 지적 반영 개정). Kokoro 품질 기준 충족 시 구현 진행, 품질 미달로 타 모델 전환 필요 시에만 사용자 승인.
- 선행: ADR 0025·0026·0027·0028(로컬 STT·요청 수명), ADR 0010(회의록), [TTS 설계](../design/local-tts.md).
- 사용자 결정: TTS는 회의록 STT에 통합하지 않는다. 별도 생성 페이지 + 채팅 응답의 선택적 재생 버튼. 엔진은 Kokoro-82M 우선·로컬·무료·교체 가능 추상화. 대형 모델 미상주로 평시 자원 점유 최소화.

## 배경과 개정 사유

초안(0061) 및 1차 개정안에 대한 독립 검증에서 다음 사항이 지적되었다:
1. 입력 원문 보관 대안의 혼선(인메모리 vs 스테이징 파일) 및 DB 원문 부재를 사용자 추가 지시처럼 표현한 점, 과장된 영구 소멸 표현(shred & unlink 등).
2. generation 전환/drain 시 인메모리 원문의 프로세스 격리 한계와 구 세대 job 복구 불가 조건 미반영.
3. HTTP job 상태 조회 계약(410 vs 200 failed)의 모순, /speak와 /jobs 간 직렬 실행 예산 미명시, `run_json_worker`의 배치 완료 계약과 청크 조기 제공 간 불일치.
4. 미래 Alembic 마이그레이션 번호(0055) 사전 예약.
5. iOS Safari 모바일 재생 안정성의 무조건적 보장 과장 및 play Promise rejection 대비 부재.
6. CPU/스레드 경합에 대한 미측정 충분성 단정, 유휴 자원 0/부모 RSS 0 과장, 부모 PID 감시와 프로세스 수명 간 모순, 날짜 발음(십월 vs 시월) 오류.
7. Kokoro 품질 통과 시에도 불필요하게 사용자를 차단하는 게이트 과대 해석.

본 2차 개정안은 위 지적을 전면 반영하여 설계 정합성을 확립한다.

## 결정

1. **별도 TTS 경로와 기존 격리**: `src/ttakkari/tts/` 독립 패키지와 `/api/tts` 라우터, 프론트 `/tts` 페이지를 신설한다. 회의록 파이프라인, 기존 STT 직렬 큐(`meetings/local_stt/jobs.py`), STT 스키마, E5 임베더(`context/embedder.py`의 자체 락)는 일체 변경하지 않는다.
2. **엔진 추상화와 모델 채택 원칙**: 부모 프로세스는 `TtsProvider` Protocol(voices·synthesize·capabilities·availability)만 본다. Kokoro 어댑터는 플러그형으로 둔다. Kokoro 한국어 품질이 실사용 기준을 충족하면 별도 승인 게이트 없이 다음 단계(WBS 5 이후)로 진행한다. **단, Kokoro 한국어 품질이 실사용 기준에 미달하여 타 모델(Piper, ChatTTS 등)로의 교체가 필요할 때에만 임의로 교체하지 않고 벤치 결과와 대안을 보고하여 사용자 승인을 받는다.**
3. **요청별 일회용 프로세스**: Phase 1 프로세스 모델은 요청별 일회용 자식 프로세스다. `model_process.run_json_worker`를 재사용하며 STT와 동일한 감독(회수·타임아웃·부모 감시·무자격증명·오프라인 강제)을 따른다. 실행 중인 자식 프로세스는 `watch_parent` 감시 스레드를 통해 부모 프로세스 수명에 종속되며, 부모 종료 시 고아 방지를 위해 자살(`os._exit(74)`)한다. 대형 모델 가중치(수백 MB)는 메모리에 상주하지 않으나 부모 프로세스의 큐/메타데이터 관리 메모리는 정상 소비된다.
4. **청크 단위 합성 및 캐시 키 통일**: 문장 청크 단위로 합성하며, 캐시 키의 원자 단위를 청크 키로 통일한다. 키는 `blake2b("tts1" ‖ engine ‖ model_revision ‖ voice ‖ speed ‖ normalize(chunk_text))`이며 파일은 `<home>/tts-cache/`에 보관한다.
5. **원문 미저장 불변성(설계상 데이터 최소화) 및 인메모리 수명 관리**:
   - DB `tts_jobs` 테이블에는 개인정보 최소화 방침에 따라 텍스트 원문을 일체 저장하지 않는다(파라미터 및 해시만 보관).
   - 비동기 job의 텍스트 원문은 서버 부모 프로세스의 **인메모리 버퍼(`_pending_texts[job_id]`) 하나로만 관리**한다(임시 디스크 파일 사용 안 함).
   - 수명: (a) 요청 접수 시 인메모리 등록 → (b) 단일 consumer가 job을 claim하고 자식 프로세스에 stdin(pipe)으로 JSON 전달 완료 즉시 부모 인메모리 참조 해제(GC 대상) → (c) 자식 프로세스는 청크별 합성 후 메모리 해제 및 종료 시 OS 가상 메모리 반환. (단, OS swap/물리 메모리 소멸은 애플리케이션이 보장할 수 없음).
   - 종료 규칙: TTL 만료(10분) 시 메모리 해제 및 `failed(input_ttl_expired)`, 취소 시 즉시 메모리 해제 및 워커 회수(`cancelled`), 실패/완료 시 즉시 해제.
6. **Generation 소유권·Fencing 및 수명 주기 정합성**:
   - TTS job은 DB 레코드에 접수한 generation/owner ID를 기록한다. 인메모리 원문은 프로세스 경계를 넘어 타 세대로 이전할 수 없으므로, 새 generation 기동 시 구 generation의 job을 복구하거나 가로채서 실행하는 것을 엄격히 금지한다.
   - 새 세대 기동만으로 기존 queued/running job을 일괄 실패 처리하지 않는다. 구 세대가 draining 중인 동안에는 자신이 보유한 인메모리 원문으로 job을 정상 완료할 수 있다.
   - 구 세대 프로세스의 종료(사망) 또는 하트비트 만료가 확인된 경우에 한해, 새 세대가 남겨진 고아 job들을 `failed(owner_process_terminated)`로 안전하게 fencing 정리한다.
7. **HTTP 상태 조회 계약 및 직렬 실행 예산 준수**:
   - `GET /api/tts/jobs/{id}`는 항상 **HTTP 200 OK**를 반환하며, 실패 시 본문 `{"status": "failed", "error_code": "..."}` 계약으로 일원화한다(410 설명 삭제).
   - 단문 동기 `/api/tts/speak`와 장문 비동기 `/api/tts/jobs`는 부모 프로세스 내 공통 `asyncio.Lock`을 공유하여 동시에 복수의 TTS 추론 프로세스가 실행되지 않도록 직렬 실행 예산을 보장한다.
   - `run_json_worker`는 프로세스 종료 시 `result.json`을 단일 배치로 반환하므로, Phase 1에서 단일 프로세스 실행 중 첫 청크 조기 제공은 지원하지 않으며(프로토콜 확장 없음), 조기 응답(TTFA 단축)은 캐시 히트 경로를 통해 달성한다.
8. **iOS Safari 모바일 재생 전략**:
   - 모바일 재생 보장을 단정하지 않고 [미검증 가설]로 다룬다.
   - 사용자 제스처 동기 시점에 단일 `HTMLAudioElement` 언락을 시도하고 동일 엘리먼트의 `src` 체이닝을 적용하되, WebKit 자동재생 정책(https://webkit.org/blog/6784/new-video-policies-for-ios/) 및 제스처 만료 버그(https://bugs.webkit.org/show_bug.cgi?id=134925)에 따른 `play()` Promise rejection을 반드시 catch한다.
   - 재생 차단 시 사용자에게 "다음 문장 터치" 안내를 표시하는 재터치 복구 UX를 필수로 구비하고, iOS 실기기 체크리스트 검증을 통과해야 한다.

## 상주를 택하지 않은 근거

대형 모델 가중치 미상주 요구를 직접 충족하며, 배포 세대 교체 시 상주 워커 풀 드레인·프리로드의 복잡도를 피하고, Kokoro 로드 비용 미확인 상태의 시기상조 최적화를 방지하기 위함이다. 캐시 미스 단문 TTFA p50이 8초(실측 전 가설)를 넘으면 상주 도입을 재검토한다.

## 대안과 한계

- **공용 슬롯 2개안**: 기존 STT 직렬 큐 및 E5 락과 불일치하여 폐기했다. 독립 직렬 큐로 분리한다. STT 4스레드(실제 설정 확인)와 TTS 2스레드(실측 전 가설)의 동시 실행 간섭은 벤치로 실측한다.
- **임시 파일 스테이징안**: 인메모리 관리로 단순화하며, 디스크 I/O 및 shred 복잡도는 Phase 1에서 제외하고 대용량 대비 미래 검토로 분리한다.
- **마이그레이션 번호**: 0055 등의 번호를 사전에 예약하지 않으며, 구현 시점의 Alembic 최신 head 및 down_revision을 기준으로 확정한다.

## 검증 범위

채택 전 필수 확인: Kokoro 한국어 품질 실측, 타 모델 교체 필요 시 사용자 승인, iOS 실기기 연속 재생 및 재터치 복구 검증, STT 동시 실행 시 상호 RTF 저하율 실측. 검증 기록은 `back/docs/tts/`에 둔다.
