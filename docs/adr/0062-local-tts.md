# ADR 0062. 로컬 TTS: 별도 페이지·엔진 추상화·요청별 프로세스 (개정)

- 상태: 초안(2026-10-20, 독립 검증 지적 반영 개정). 병행 벤치 세션의 Kokoro 측정 결과 및 품질 게이트 승인 후 채택 판단.
- 선행: ADR 0025·0026·0027·0028(로컬 STT·요청 수명), ADR 0010(회의록), [TTS 설계](../design/local-tts.md).
- 사용자 결정: TTS는 회의록 STT에 통합하지 않는다. 별도 생성 페이지 + 채팅 응답의 선택적 재생 버튼. 엔진은 Kokoro-82M 우선·로컬·무료·교체 가능. 유휴 자원 점유 최소화.

## 배경과 개정 사유

초안(0061)에 대한 독립 검증에서 (1) ADR 번호 0061 충돌(game-version-history 사용 중), (2) Alembic 0053 번호 충돌(작업 트리 미추적 0053/0054 존재), (3) 기존 STT/E5 코드에 존재하지 않는 공용 슬롯 가정 모순, (4) DB 원문 미저장과 비동기 job 합성 간 텍스트 수명 미정의, (5) iOS Safari 청크 연속 재생 시 제스처 상실 위험, (6) 한국어 품질 미달 시 모델 선택 게이트 부재가 지적되었다. 본 개정안(0062)은 이를 전면 보완한다.

## 결정

1. **별도 TTS 경로와 기존 격리**: `src/ttakkari/tts/` 독립 패키지와 `/api/tts` 라우터, 프론트 `/tts` 페이지를 신설한다. 회의록 파이프라인, 기존 STT 직렬 큐(`meetings/local_stt/jobs.py`), STT 스키마, E5 임베더(`context/embedder.py`의 자체 락)는 일체 변경하지 않는다.
2. **엔진 추상화와 품질 게이트**: 부모 프로세스는 `TtsProvider` Protocol(voices·synthesize·capabilities·availability)만 본다. Kokoro 어댑터(워커 모듈·모델 경로·음성 목록·청크 권장값·출력 형식)는 플러그형으로 둔다. **Kokoro 한국어 품질이 실사용 기준에 미달할 경우 임의로 타 모델로 교체하지 않고, 측정 결과와 대안을 사용자에게 보고하여 최종 결정을 받는 [GATE]를 통과해야 한다.**
3. **요청별 일회용 프로세스**: Phase 1 프로세스 모델은 요청별 일회용 자식 프로세스다. `model_process.run_json_worker`를 재사용하며 STT와 동일한 감독(회수·타임아웃·부모 감시·무자격증명·오프라인 강제)을 따른다. 유휴 타임아웃 상주는 쓰지 않는다.
4. **청크 단위 합성 및 캐시 키 통일**: 문장 청크 단위로 합성하며, 캐시 키의 원자 단위를 청크 키로 통일한다. 키는 `blake2b("tts1" ‖ engine ‖ model_revision ‖ voice ‖ speed ‖ normalize(chunk_text))`이며 파일은 `<home>/tts-cache/`에 보관한다.
5. **원문 미저장 및 비동기 Job 수명 규칙**: 개인정보 최소화 원칙에 따라 DB `tts_jobs` 테이블에는 텍스트 원문을 일체 저장하지 않는다(해시·파라미터만 보관). 비동기 합성 대상 텍스트는 서버 인메모리 버퍼(또는 단기 0600 권한 임시 파일)에 유지하고, 워커 프로세스가 stdin으로 수신하여 합성을 시작한 직후 즉시 파기한다. 서버 재시작 시 잔여 job은 `failed(server_restarted_input_purged)`로 종결하며, 클라이언트에 410 상태를 반환하여 클라이언트 원문 기반의 재요청을 유도한다.
6. **큐 구조 및 동시성 제어**: 기존 STT/E5 큐 구조는 수정하지 않는다(공용 슬롯 폐기). TTS는 독립된 직렬 큐(`tts/jobs.py`)를 사용한다. Mac Studio M5 Max 64GB 환경의 풍부한 CPU 코어(18코어)를 활용하여 STT와 TTS의 동시 실행을 기본적으로 허용한다. STT 4스레드 + TTS 2스레드 예산 하에서 동시 실행 시의 상호 RTF 저하율을 벤치로 실측하여 간섭 영향을 검증한다.
7. **오디오 서빙**: `<audio>` 재생용 오디오는 단기 토큰 URL(`/api/dl/tts/{token}`, TTL 10분)로 서빙하여 Authorization 헤더 부재 문제를 해결한다.
8. **iOS Safari 모바일 재생 전략**: 사용자 제스처(클릭/터치) 시점에 단일 `HTMLAudioElement` 인스턴스를 즉시 언락(무음 재생)하고, 청크 전환 시 동일 엘리먼트의 `src` 속성을 체이닝하여 재생함으로써 iOS의 비동기 제스처 상실 문제를 방지한다.

## 상주를 택하지 않은 근거

유휴 자원 0 요구를 충족하지 못하고(타임아웃 대기 중 메모리 점유), 세대 교체 드레인·프리로드·헬스체크 복잡도가 필요하며, Kokoro 로드 비용 미확인 상태의 시기상조 최적화이기 때문이다. 캐시 미스 단문 TTFA p50이 8초(가설, 벤치로 확정)를 넘으면 유휴 타임아웃 상주 도입을 재검토한다. 전환 시에도 일회용 프로세스 경로는 폴백으로 유지한다.

## 대안과 한계

- **공용 슬롯 2개안**: 초기 초안에서 검토되었으나, 현재 STT가 단일 컨슈머 직렬 큐이고 E5가 별도 락을 쓰는 구조와 불일치하며 "STT 큐를 건드리지 않는다"는 원칙을 위배하므로 폐기했다. 독립 직렬 큐 + OS 프로세스 동시 실행 허용으로 단순화한다.
- **회의록 STT 통합안**: 사용자가 거부했다. TTS 생성과 회의 전사는 입출력 및 수명이 달라 통합 시 스키마가 오염된다.
- **바이트 스트리밍안**: Phase 2 후보다. 청크 단위 완성이 iOS Safari의 오디오 연속 재생 안정성 및 캐시 결합 측면에서 월등히 단순하고 안정적이다.
- **원문 DB 영구 저장안**: 개인정보 보호 및 데이터 최소화 원칙에 위배되므로 배제했다. 단기 인메모리/임시파일 수명 관리와 재시작 시 실패 처리로 불변성을 달성한다.

## 검증 범위

채택 전 필수 확인: Kokoro 한국어 품질·권장 청크·출력 형식·로드 시간·메모리(병행 벤치 세션), 한국어 품질 게이트 사용자 승인, iOS 실기기(Safari/PWA) 연속 재생 검증, STT 동시 실행 시 RTF 저하율 실측, Alembic 번호(구현 시점 최신 head 다음, 작업 트리 0055_local_tts_jobs 이후 확인). 검증 기록은 `back/docs/tts/`에 둔다.
