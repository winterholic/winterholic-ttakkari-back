# ADR 0073: 저장소 가치 평가(백엔드)

## 상태
구현됨(2026-11-15). 프론트는 범위 밖.

## 배경
GitHub 저장소 하나를 종합 품질로 평가해 축별 점수·등급·약점 Top3·보강안을 낸다.
단일 사용자가 재미로 가끔 쓴다. 핵심 제약은 LLM 토큰 최소 사용이다.

## 결정

1. **5개 축·항목 0~5점.** 항목 정의·유형별 가중치·보강안 문장은
   `repo_appraisal/rubric.py` 상수(`ITEMS`·`WEIGHTS`·`ADVICE`)에 둔다.
   근거 수치(`evidence`) 없는 점수는 만들지 않고, 5점은 기준을 넘어선 가치에만 준다.
   종합은 축 점수 가중합(0~100), 등급은 A+ 90·A 85·B+ 80·B 70·C 60·그 아래 D.
   계산은 전부 순수 함수다(LLM 은 산수 안 함).
2. **저장소 유형 규칙 분류.** `library|app|docs|experiment|unknown`을
   선언 파일·진입점·마크다운 비율·규모로 가른다. 애매하면 `unknown` 기본 가중치.
   `docs` 는 코드·구조 가중치를 낮추고 테스트 항목을 감점에서 뺀다.
3. **하네스 축은 하네스 조회 기준 재사용.** 존재 확인 대상·길이 한도(400줄·
   20,000자·AGENTS.md 32KiB)·깨진 참조·중복 이름 판정을 `harness_view`와 같은
   상수·정규식으로 본다. 하네스 파일이 하나도 없으면 `na`로 두고 가중치에서
   제외·재정규화한다(감점 아님).
4. **약점 Top3은 가중 손실 순.** `(5-점수)/5*100*축가중치/축항목수`로 재점검 없이
   계산하고, 보강안은 항목별 템플릿 문장이다(LLM 불필요).
5. **LLM 은 평가당 최대 1회.** 구조화 JSON(축별 점수·인용·신뢰도·한 줄 총평)만
   받는다. 인용이 없거나 증거 패킷에 없는 경로를 인용하면 해당 항목을
   `unverified`로 폐기하고, 점수는 0~5 로 clamp 한다. 독창성 판정은 항상
   신뢰도 낮음 표시를 달고 종합 가중치를 작게 둔다.
6. **호출은 접수 일회성 패턴 재사용.** 상주·도구·전역 하네스 없이
   (`--setting-sources local`·hook 끄기 등) 최소 컨텍스트로 부르고, 증거는
   stdin 으로만 넘긴다. 엔진·모델·증거 상한·시간 제한은
   `repo_appraisal_engine`·`repo_appraisal_model`·`repo_appraisal_evidence_max_chars`
   (기본 40000자)·`repo_appraisal_timeout_seconds` 설정이다.
   호출 실패·출력 오류면 결정론 점수만으로 완료하고 주관 항목은 미채점,
   `llm_used=false`로 둔다(실패 처리 안 함).
7. **캐시.** 같은 `(owner/repo, head_sha, mode, rubric_version)` 완료 행이 있으면
   새로 계산하지 않고 그 행을 돌려준다. `force=true` 로만 다시 계산한다.
8. **수집은 GitHub API 만.** 읽기 전용 클라이언트·계정 선택·캐시·대상 파싱을
   그대로 쓰고 토큰 불변식(ADR 0042 §5)을 지킨다. 클론 없음.
   quick 고정 7회(repo·트리·README·커밋·기여자·릴리스·이슈/PR 겸용)+표본 8회로
   15회 상한 안, deep 는 표본 확대분만큼 더 쓴다. 워크플로는 트리에서 읽고,
   이슈 목록 응답에서 PR 을 갈라내 별도 호출을 아낀다. 통계 202는 2회 짧게
   재시도 후 해당 항목만 `unavailable`로 둔다. 그 외 조회 실패는 0점 위장을
   막으려고 실행 전체를 실패시킨다.
9. **저장·이력.** `repo_appraisals` 테이블(실행 중 `result`에는 진행 단계만).
   이력 조회는 직전 완료 행과의 점수 차이(delta)를 함께 낸다.
10. **API 는 소유자 전용.** `POST /api/repo-appraisals`(있으면 200 재사용,
    없으면 202 백그라운드), `GET /{id}`, `GET ?owner=&repo=&limit=`.
    MCP·에이전트 라우터 없음, 라우트 인벤토리에 owner-scoped 등록.
    재시작 시 `running`·`queued` 행은 실패(`서버 재시작으로 중단`)로 정리한다.
    queued 도 워커가 없어 재개가 안 되니 함께 둔다.

## 설계 대비 변경
- `repo_appraisal_model` 하나가 아니라 엔진 설정을 분리했다
  (`repo_appraisal_engine`, 기본 `codex:gpt-6-luna`). 호출부에서 엔진을
  고정 문자열 파싱 없이 고르게 하려는 것이다.
- deep 모드 요청 수는 15회를 넘긴다(표본 확대분, 최대 20회 안팎). quick 은
  15회 상한을 지킨다.
- 재시작 정리는 `running` 뿐 아니라 `queued` 도 실패로 둔다(재개 워커 없음).
- GitHub 계정은 행에 저장하지 않고 메모리에만 둔다(재시작이면 행도 실패라 정합).

## 불변식·한계
- 토큰은 메모리 전용, 응답·로그에 없음(ADR 0042 §5). 상류 401은 502로만 낸다.
- 오류 본문 `{code,message}`, 응답은 화이트리스트 필드만.
- 순환 구조·이슈 처리율은 표본 한정 근거다. 트리 잘림·표본 한정은 결과에
  표시한다. 빈 저장소는 점수 없이 빈 사실로 완료한다(`head_sha: empty`).
