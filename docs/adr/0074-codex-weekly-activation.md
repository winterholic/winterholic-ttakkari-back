# ADR 0074. Codex 구독의 저빈도 조회와 주간 활성화 예약

- 상태: 구현 후보, 운영 배포 및 실제 주간 경계 관측 전(2026-11-18). 2026-11-21 첫 주간 경계 관측 결과로 새 창 판정 규칙을 개정했다(아래 "실행과 중복 방지").
- 요청: 평소 조회를 줄이고 알려진 주간 초기화 시각의 10초 뒤에 확인하여 필요한 최소 요청만 실행한다.
- 조사: [공식 문서·CLI 0.166.0 스키마와 실험](../research/codex-subscription-20261118.md).

## 결정과 범위

기존 `EngineAccount`, `AppSetting`, `AccountUsageSample`, `ScheduledAction`, 알림 수신 설정을 재사용한다. 새 데몬·스케줄러·인증 저장소·DB 마이그레이션을 만들지 않는다. 현재 활성화 제공자는 Codex뿐이다. 계정별 상태에 provider를 두어 다른 제공자의 정책을 뒤에 추가할 수 있다.

기존 사용량 수집기는 Codex 계정을 처음 볼 때 영속 예약을 복구하고 직접 고빈도 조회하지 않는다. 이후에는 DB 예약의 존재·상태만 점검한다. 누락된 예약은 복구하고 반복 실패한 큐 작업은 12시간 뒤로 늦춰 외부 조회의 무한 재시도를 막는다. 평소 간격은 12시간이며 주간 시각을 알면 `min(다음 일상 조회, resetsAt+10초)`를 예약한다. 주간 경계는 초기화 직전 폴링 없이 도래 후 확인한다. 미확인 시 30·60·120·240·450초 재확인하며, 최초 확인 후 15분 또는 6회로 제한한다. 서버 재시작 때는 최근 60초 내 확인을 재사용하고 그 밖에는 현재 상태를 한 번 재확인하도록 예약을 복구한다. 기존 큐의 DB 스캔 주기·OS·네트워크 때문에 실제 시작은 목표 시각과 다를 수 있다.

예약 교체와 실행 준비는 계정 행의 `FOR UPDATE` 잠금 안에서 한다. 상태가 가리키는 예약 ID와 실행 payload를 대조하므로 취소 후 남은 leased 작업은 실행하지 않는다. 계정별 주기는 확인 대상이었던 기존 주간 `resetsAt`으로 식별한다.

## 조회와 인증

새 수집 경로는 CLI 소유의 `account/read`와 `account/rateLimits/read`를 사용한다. 모델 turn/thread 생성 RPC는 클라이언트에서 금지한다. 일상 조회는 토큰 강제 갱신을 요청하지 않으며, 배경 조회는 재설정 크레딧 상세 추가 조회를 생략한다. 초기화 판단에는 세션 로그·캐시를 쓰지 않는다. 기존 화면의 수동 새로고침/재설정 크레딧 기능은 기존 인터페이스를 유지한다.

`windowDurationMins`가 300/10080일 때만 5시간/주간으로 구분하고, 빠지거나 알 수 없는 값은 주간 0%로 만들지 않는다. `ordinaryUsageAllowed`가 true일 때만 포함 사용이 허용된 것으로 취급한다. null/false에서 퍼센트·시각만으로 사용 가능 상태를 추정하지 않는다. 인증/전송/한도 오류는 구분하고 원문 stderr·토큰은 저장하지 않는다. RPC가 모델 요청을 하지 않는 것과, 조회가 서버의 주간 주기를 시작시키지 않는다는 보장은 서로 다르다. 후자는 아직 확인되지 않았다.

CLI 자체가 인증 갱신·상태 DB 쓰기를 할 수 있다. 읽기 RPC를 파일 시스템 무변경으로 주장하지 않는다. 인증 파일 복사·직접 OAuth 갱신·API 키 전환은 하지 않는다. 실제 프로젝트와 기존 대화에는 thread/turn RPC를 보내지 않는다.

## 실행과 중복 방지

미사용 상태로 보이는 만료 창의 신선한 0%와 포함 사용 허용이 확인되면 활성화 후보가 된다. 다음 주간 창이 이미 미래로 이동한 경우(2026-11-21 개정)에도 그 창이 0%이고 `resetsAt`이 관측 시각+7일의 120초 안이면 아직 시작되지 않은 창으로 보고 활성화 후보로 취급한다. 운영 관측에서 미사용 창의 `resetsAt`은 관측 시각+기간으로 보고됐다. 사용률이 0보다 크면 선사용으로 보고, `resetsAt`이 그보다 이르면 이미 시작된 창이라 사용자 소량 사용을 0%와 구분할 수 없어 자동 요청을 생략한다. 0% 반올림에 가려진 극소량 외부 사용은 최소 요청 한 번을 더 보내는 비용으로 수용한다. 근거와 관측값은 [조사 11절](../research/codex-subscription-20261118.md). 따까리의 해당 계정 실행 기록과 현재 lease도 선사용 판단에 이용한다. 외부 CLI/앱의 미세한 사용과 조회-실행 사이의 외부 요청을 원자적으로 감지할 공식 수단은 확인하지 못했다.

모델 실행 전에 dispatch 주기·시각을 DB에 커밋한다. 같은 계정·주기의 다른 인스턴스/수동 요청은 이 표식을 우회하지 못한다. 외부 요청 직후 프로세스가 죽으면 성공과 미전송을 확정할 수 없으므로 unknown으로 남기고 다시 보내지 않는다. 외부 모델 API에 대한 exactly-once 보장이 아니다. 명백히 프로세스를 만들기 전의 OSError만 최대 두 번 시도하며, 인증·한도 오류와 실행 후 불명 오류는 무작정 재시도하지 않는다.

별도 임시 cwd에서 `exec --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -s read-only`를 실행한다. ChatGPT 로그인과 OpenAI provider를 강제하고 API 키·기존 세션 ID·하네스 비밀 환경 변수를 자식에게 넘기지 않는다. 훅·MCP 사용자 설정·실행 도구를 끄고 짧은 OK 응답을 요청한다. 기본 모델은 현재 따까리의 Codex 기본 작업 모델 `gpt-6-luna`, reasoning은 low다. 실제 최소 소모량/모델 접근성은 아직 측정하지 않았다.

실행 전후 사용량·다음 초기화 시각·실제 반환된 토큰 수를 보존한다. 토큰 수나 초기화 시각 변화가 없더라도 임의의 효과를 만들어 보고하지 않는다. 자동 설정 때문에 생략했거나 확인 횟수를 소진했지만 아직 모델을 보내지 않은 주기는 사용자의 수동 활성화로 다시 확인할 수 있다. 이미 보낸 요청은 수동 실행으로도 재전송하지 않는다.

## UI·알림·호환성

기존 사용량 카드에 예약·마지막 조회·마지막 결과·ON/OFF·수동 확인/활성화를 추가한다. 날짜는 초 단위 KST이며 단기/주간 수치는 기존 창을 유지한다. 전후 비교는 펼쳐서 확인한다. 오류/empty/unknown을 성공으로 바꾸지 않는다. 초기화 확인 예약과 모델 요청 시각을 구분하고 실제 주기 효과가 미검증임을 표시한다.

기존 알림함·Web Push 경로에 `push.subscription` 유형을 추가한다. 사용자 수신 설정과 주기별 중복 키를 적용하고, 알림 실패 때문에 모델 요청을 다시 보내지 않는다. 자동 실행 결과와 확인 횟수 소진을 알린다.

이전 세대는 새 action 유형을 집지 않는 기존 큐 규칙을 따른다. 롤백하면 새 예약·상태는 남지만 구버전은 실행하지 않는다. 되돌린 버전의 이전 Codex 고빈도 수집 정책이 다시 적용될 수 있다.

## 현재 검증 경계

시간 주입·모의 RPC/CLI와 실제 격리 PostgreSQL로 예약 시각 변경·중복·재시작·dispatch fence·수동 실행·실패 표시를 검증한다. 프론트는 합성 데이터로 실 브라우저와 컴포넌트 테스트를 사용한다.

현재 중첩 Codex 샌드박스에서 실제 등록 계정 App Server는 initialize 응답 전에 `sandbox_denied (exit 1)`로 종료했다. 이 결과를 호스트·배포 백엔드의 실패로 확대하지 않는다. 보호 경로·다른 엔진으로 우회하지 않는다. 운영 배포 이후 지원 API를 통한 실 계정 조회와 실제 주간 경계의 전후 관측이 남아 있다. 첫 모델 사용이 다음 주간 시각을 정하는지, 조회 자체가 창을 시작하는지는 공식 보장도 실제 관측도 확보하지 못했다. 2026-11-21 첫 주간 경계에서 초기화 확인은 실행됐으나 위 개정 전에는 자동 요청이 나가지 않았다. 개정 후 실제 활성화 결과는 배포 뒤 처음 오는 실제 경계 관측 전까지 미검증이다. 미사용 창에는 경계가 오지 않으므로 이 규칙은 사용으로 시작된 창이 끝나는 경계에서 작동한다.
