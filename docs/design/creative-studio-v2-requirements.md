# AI-native 영상 스튜디오 v2 — 사용자 요구사항과 실행 계약

기준: 2026-10-22 사용자 신규 지시. 이 문서는 구현 완료 보고가 아니다.
기존 ADR 0065의 포맷/장면/도구 카탈로그는 호환 대상으로 보존하되 새 아키텍처를 제한하지 않는다.

## 목표와 불변 조건

특정 템플릿·고정 길이에서 벗어나 제작 의도를 해석하고 전문 기술을 조합하는 스튜디오를 실제 구현한다.
기획, 설계, 기존 WBS/PMS 갱신, 개발, 테스트, 실제 영상 제작, 품질 검증까지 범위다.
단순 목록 등록, 빈 SKILL.md, 실행되지 않는 레시피, MP4 생성 성공만으로 완료 처리하지 않는다.
기존 따까리 스킬·지식 도서관·오케스트레이터·ML 실험 플랫폼에 연결한다. 별도 중복 시스템을 만들기 전에 기존 계약을 찾는다.
사용자 새 지시가 과거 템플릿 및 2~4분 범위보다 우선한다. 기존 결함 수정·다른 작업 변경은 보존한다.
신규 유료 과금은 승인 없이 발생시키지 않는다. 기존 공용 lease와 실행·복구·보안 경계를 약화하지 않는다.

## 실행 자원: 네 레지스트리

- Tool: Remotion, React, Three.js, React Three Fiber, Blender, Godot, ComfyUI, ArtCraft, FFmpeg, SVG/Canvas, 오디오 편집·합성. 실제 설치 상태·버전·실행 환경·지원 능력·입출력·자동화 인터페이스를 측정한다.
- Model: 이미지/영상 생성, TTS, STT, 음악, 이미지 편집, 업스케일, 프레임 보간, 멀티모달 평가. 품질·시간·메모리·비용·라이선스·기능·증거 시각을 기록한다. 준비/미검증을 실행 성공으로 승격하지 않는다.
- Skill: 실행 가능한 입력·출력 규격, 의존성, 실행 코드, 검증 규칙, 성공·실패 사례. 모델/도구 이름만으로 전문 스킬을 구현했다고 하지 않는다.
- Recipe: 여러 스킬·도구의 실행 계획. 스타일/장면을 재현하며 검증 사례에 연결한다. 미실행/누락 능력을 표시하고 검증된 대안을 선택한다.

## 매칭·제약 해석

처리 순서: 의도·제약 추출 → 유형·세계관 → 시각·캐릭터 → 서사·장면 → 장면별 촬영·모션·조명·음향 → 필요 능력 → 실행 가능 Tool/Model/Skill 탐색 → 검증 레시피 우선 검색 → 누락·호환성 확인 → 실행 계획·품질 기준.
다대다 관계: requires, prefers, compatible_with, conflicts_with, alternative_to, produces, validates_with.
필수와 선호를 구분한다. 선호가 부족해도 품질이 더 나은 대안은 허용한다. 필수 의존 누락·충돌은 설명과 대안을 반환한다.
사용자 요청 문자열을 사전의 단어 포함 여부로만 분류하는 구현은 거부한다. 의도 추출 결과를 타입/제약으로 검증하고, 능력 탐색·충돌 해석은 재현 가능해야 한다.

## Style DNA

사용자 원문이 열거한 필드는 15개다: style_id, visual_identity, palette, character_proportions, materials, lighting, camera_language, motion_language, environment_rules, sound_identity, reference_assets, positive_examples, negative_examples, quality_constraints, compatible_skills.
`version`은 사용자 콘텐츠 필드가 아니라 시스템 관리 메타데이터다. 버전 고정 요구를 구현하기 위해 저장·상속 계약에서 별도 필드로 둔다. 따라서 사용자 열거 필드는 15개이고 `version`을 16번째 사용자 필드로 세지 않는다.
자연어뿐 아니라 이미지·영상·코드·렌더 설정·성공/실패를 참조한다. 작품 단위 상속·수정·버전 고정이 가능해야 한다.
예: 귀여운 3D + 공포 조명 + SF 세계관. 상충 규칙은 출처와 해결 근거를 남기며 묵시적 덮어쓰기를 하지 않는다.

## 길이 정책 — 마지막 수정 지시가 정본

세 개 길이 모드 설계는 폐기한다. **AI 자동 결정 + 선택적 희망 러닝타임**으로 통합한다.
기본 자동. UI 선택지: 자동, 15초, 30초, 1분, 2분, 3분, 5분, 10분, 15분, 직접 입력.
직접 입력은 1~900초. 45초·90초 등은 직접 입력으로 가능하다. 희망 시간은 정확한 출력 보증이 아님을 명확히 쓴다.
AI 계획 후 예상 러닝타임과 판단 이유를 렌더 전에 보여주고 수정 가능하게 한다.
발화가 거의 없는 짧은 정보 항목 세 개의 경우, 600초 희망은 내용을 임의 반복하지 않는 soft target이다. 세 장면의 늘림 상한이 24초라면 계획은 `deviated` 24초가 되고, 이유·이탈률을 화면에 보여 준다. 긴 결과가 필요하면 내용을 보태거나 사용자 승인 대안을 골라야 한다.

먼저 정보량·서사 구조·실제 발화 예상 시간·음악 길이/구간·적절한 장면 지속 시간·장르/목적·이해/몰입에 필요한 길이를 계산한다.
희망 시간이 있으면 대본과 장면 구성을 그 근처로 조정한다. 기본은 soft target이며 과도한 이탈은 설명과 대안을 제시한다.
무의미한 장면으로 채우거나 중요한 정보를 임의 삭제하지 않는다. 프레임 단위 계산·오디오 실측으로 최종 재계산한다.

### R21 장면 입력·내레이션 자막 실행 계약 (2026-10-23 후속)

- 이미지 prompt는 전체 brief의 장면 지시를 모든 shot에 복사하지 않는다. `장면 N:`으로 구조화된 요청이면 공통 소개와 해당 장면 절만 전달하고, 비구조화 brief에서는 승인된 해당 scene narration/title을 shot 지시로 사용한다.
- 계획과 Comfy receipt를 scene별로 추적한다. 생성 receipt는 실제 prompt 원문과 UTF-8 SHA-256을 저장하고 Comfy receipt의 prompt hash와 일치해야 한다. 이 연결은 입력 추적 근거이며, 출력 이미지가 의미 요구와 일치한다는 판정은 별도 시각 검수로 남긴다.
- R21 정지 이미지 경로는 정지 이미지 기반 슬라이드쇼로 설명한다. 이미 연결된 FFmpeg animation/transition 선택만 적용하고, 장면 prompt 개선이나 정지 이미지 지속을 영상 생성 모션 지원으로 표현하지 않는다.
- 제작 dispatch의 `caption_mode`는 `narration`(기본) 또는 명시적 `title_only`다. narration 모드에서 대본이 비어 있는 장면은 제목 fallback으로 기록한다. narration 자막은 화면 폭의 84% 안전영역 안에서 두 줄 이하 cue로 나누고 실제 장면별 음성 asset 길이 안에 배치한다. 단어 단위 오디오 정렬이 없으면 타이밍은 추정으로 표시한다.
- 두 모드는 서로 다른 명세다. `C10.subtitles`와 R21의 필수 능력 `edit.captions`는 "읽을 수 있는 자막이 화면에 있다"만 요구하며 대본이 자막이어야 한다고 정하지 않는다. 따라서 제목만 있는 영상은 `title_only`로 명시했다면 의도된 결과이고 모드 위반이 아니다. 브리프가 내레이션 자막을 기대하는데 화면에 제목만 나오면 모드 선택 오류이거나 구버전 기본 동작이다. 판정은 dispatch 기록의 `caption_contract`(모드, `plan_selects_subtitles`, 대본 장면, 제목 자막 장면, notices)로 구분한다. `title_only`가 대본 있는 장면에서 선택되면 notices에 대본 자막이 나오지 않는다고 남긴다.
- revision당 dispatch는 한 번이라 이미 기록된 모드와 다른 `caption_mode`를 뒤늦게 요청하면 적용되지 않으며, 응답에 `caption_mode_request_ignored`로 알린다. 다른 모드는 새 revision 승인 후 dispatch한다. 구간의 stale 판정(`outdated_segments`)은 기록된 `caption_mode`로 run key를 계산한다.
- 기계 미디어 QA 성공은 장면 내용·시청 가치·발음·음악과 음성의 청감 품질을 입증하지 않는다. 음향 청취와 장면 의미 검수는 실행한 경우만 별도로 기록한다.

### R21 Style DNA 렌더 설정 입력 계약

- 현재 슬라이드쇼 렌더러가 실제 소비하는 Style DNA 값은 `motion_language.params.animation` (`still`, `zoom_in`, `zoom_out`, `pan`, `pan_down`, `pulse`), `motion_language.params.transition` (`fade`, `cut`), `visual_identity.params.caption_style` (`bottom_card`, `center_highlight`, `title_card`, `code_overlay`)뿐이다. 범위는 계획 전체이며 각 장면에 동일 적용한다. 다른 값은 지원된 것으로 표시하지 않고 dispatch receipt의 `style.ignored`에 남긴다.
- MCP `creative_v2_styles`는 렌더러가 읽는 facet/param/허용 값을 목록으로 제공하고, `creative_v2_style`은 특정 immutable version의 `render_effects.applied`/`ignored`를 미리 본다. 단순히 Style DNA가 목록에 있거나 저장됐다는 사실만으로 렌더 적용을 판정하지 않는다.
- MCP `creative_v2_style_put`은 엄격한 `StyleDNADoc`만 받는다. 미지 필드·알 수 없는 경로 입력은 거부하며, `dry_run=true`로 저장 전 검증/효과 미리보기를 제공한다. 버전은 불변이고 내장 seed 버전을 덮어쓸 수 없다. 참조는 콘텐츠 해시로 고정한다.
- 새 계획의 `style`에는 카탈로그 ID가 아니라 `{style_id, version}` 참조를 넣는다. 승인된 plan revision은 Style DNA hash를 고정한다. 다른 편에 다른 모션/전환/자막 스타일을 적용할 때는 새 Style DNA version과 새 계획/승인을 사용한다. 실제 확인은 dispatch의 `style.applied` → 렌더 project scene 설정 → 렌더 이미지의 시각 검수 순서로 한다.
- 이 계약은 계획 단위 스타일 선택만 지원한다. 장면마다 다른 Style DNA 값을 보내는 기능은 노출하지 않는다.
