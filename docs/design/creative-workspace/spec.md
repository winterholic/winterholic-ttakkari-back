# Creative Tool Workspace · 통합 UI·사용 흐름 설계 (WBS 15.4 U01~U06)

작성 2026-10-15, 담당 Claude Sonnet high. 이 문서와 `prototype/`은 **검토용 시안과 상태 명세**다. 정식 설계 완료가 아니다. 이유와 남은 의존은 §10에 있다.

## 0. 전제와 읽는 법

- 13개 앱 중 **실제로 설치·호출을 확인한 것은 하나도 없다.** 이 문서의 모든 앱 이름·버전·기능·테스트 결과는 시안용 가상 값이거나 "확인 필요"다. 프로토타입 화면에도 모든 줄에 "가상 예시" 표식이 붙는다.
- 앱 이름 중 PhotoCraft·FilmCraft·VectorCraft·PdfCraft·FigCraft·GridCraft는 사용자 요청 원문에 있고, DesignCraft는 PMS 노트가 인용한 공식 사이트 링크에서만 확인됐다. 나머지 6개는 이름이 없다. 화면에서는 "후보 8~13"으로 둔다.
- 새로 만들지 않는다: 편집기, 실행 계층(Run), 반출 통제(File Broker), 결과물 저장(Artifact), 결과물 뷰어(ArtifactViewer), 후속 지시(FollowupComposer), 작업 캔버스, 디자인 시스템. 이 문서는 이것들 위에 얹는 **화면과 상태**만 정한다.
- "확인 필요"는 코드나 실험으로 확인하지 못한 항목이다. 이 표시가 붙은 값 위에 결론을 세우지 않았다.

기준 코드: front `b8bd459`(2026-10-15), 디자인 시스템 `3599f2f`. front에는 다른 작업(체크리스트)의 미커밋 변경이 있어 건드리지 않았다.

## 1. U01 · 정보 구조·동선·기존 화면과의 관계

### 1.1 진입 위치

기존 셸 규칙(`front/src/shell/features.ts`)을 따른다. 새 기능은 라우트를 만들고 `FEATURES`에 항목 하나만 넣으면 데스크톱 "부가 기능"과 모바일 "더보기"에 같이 나타난다. 하단 탭 칸(채팅·작업·메모·캘린더·더보기)은 비어 있지 않으므로 탭을 늘리지 않는다.

| 항목 | 제안 |
|---|---|
| FEATURES 항목 | `{ root: "creative", to: "/creative", icon: "layers", label: "크리에이티브", description: "이미지·영상·문서 작업을 말로 요청하고 결과를 확인" }` (아이콘 이름은 `ui/Icon.tsx` 매핑에 추가 필요) |
| 라우트 | `/creative` → `/creative/work` 로 이동. `/creative/work`, `/creative/library`, `/creative/history`, `/creative/tools` |
| 화면 안 이동 | 헤더 아래 탭(`.tk-tablist`) 4개: 작업실 · 결과물 · 실행 이력 · 도구. 도구 관리는 설정 성격이라 마지막에 둔다 |
| 문맥 줄 | 탭 아래에 항상: 프로젝트 › 작업. 모든 화면에서 같은 값을 쓴다 |

탭 이름은 사용자 원문의 "통합 작업실 · 결과물 라이브러리 · 실행 이력 · 도구 관리"를 줄였다. 화면 안 제목은 원문 이름을 그대로 쓴다.

### 1.2 화면맵

```
부가 기능 › 크리에이티브
 ├─ 작업실  /creative/work?project=&task=&version=&view=
 │    ├─ 미리보기·버전·비교·승인 영역
 │    ├─ 요청·진행 스레드 (Run 카드 재사용)
 │    └─ 컴포저 (파일 첨부)
 │         ├─ [승인 대화상자]  [취소 확인]  [도구 선택 이유]  [원본 앱 열기]
 ├─ 결과물  /creative/library?project=&task=&type=&role=&tool=&q=&item=
 │    └─ 상세(데스크톱 오른쪽 패널 / 모바일 전체 화면): 미리보기 · 버전 · 입력 파일 · 정보
 ├─ 실행 이력  /creative/history?project=&task=&st=&tool=&q=&run=
 │    └─ 상세: 오류 요약 · 단계 · 자원 · 결과 링크 · 재시도 · 로그
 └─ 도구  /creative/tools?tool=
      └─ 상세: 상태 5축 · 활성화 · 기능과 제약 · 테스트 · 설치 안내 · 복구 · 열기 방식
```

모든 화면 상태는 주소로 복원된다. 프로토타입은 해시(`#work?s=compare&p=p1&t=t1`)로 같은 구조를 흉내 낸다.

### 1.3 네 화면의 역할과 기존 화면과의 중복 해소

| 새 화면 | 하는 일 | 기존 화면 | 겹치는 부분 | 해소 방법 |
|---|---|---|---|---|
| 작업실 | 한 작업의 요청·진행·미리보기·수정·승인 | **작업 캔버스** `/tasks`(지시 트리) | 지시와 진행 | 캔버스는 에이전트 지시 트리 전체의 지도다. 크리에이티브 작업은 캔버스의 노드로 그대로 존재하고, 작업실은 그 노드의 미디어 전용 보기다. 작업실 문맥 줄에 "작업 캔버스에서 보기" 링크. 캔버스 화면은 바꾸지 않는다 |
| 작업실 | 미리보기·후속 지시 | **작업 공간** `/workspace`(세션 결과물 뷰어 + 후속 지시) | 뷰어와 컴포저 | 별도 뷰어를 만들지 않는다. 미리보기는 ArtifactViewer를, 후속 지시는 FollowupComposer를 재사용하고 버전·승인·도구 줄만 위에 얹는다 |
| 결과물 | 파일·버전·역할 | **보관함** `/library`(모든 Artifact) | 파일 목록 | 저장소와 쿼리는 하나다. 결과물 화면은 같은 Artifact를 "작업 → 버전 계보"로 묶어 보여 주는 뷰다. 보관함 행에서 "크리에이티브에서 열기"로, 결과물 상세에서 "보관함에서 보기"로 양방향 링크 |
| 실행 이력 | 도구 중심 실행 기록 | **실패한 작업** `/tasks/failed`, Run 상세 | 실패 기록 | 같은 Run 데이터를 도구·파일·시도 기준으로 본다. 필터 "문제 있음"이 실패 목록과 같은 행을 보여 준다. 행에서 기존 Run 상세로 링크 |
| 도구 | 후보 도구의 상태와 설정 | (없음) | 없음 | 신규. 설정(`/settings`)이 아니라 이 영역 안에 둔다. 에이전트 노출 범위를 정하는 곳이기 때문이다 |

**결정이 필요한 것**: 결과물을 별도 탭으로 둘지, 보관함 안의 "보기 전환"으로 둘지. 이 시안은 요구 원문(4화면)을 따라 탭으로 두되 데이터와 컴포넌트는 보관함과 공유한다. 대표 확인 필요.

### 1.4 문맥 유지 규칙

- 프로젝트와 작업은 URL(`project`, `task`)이 정본이다. 화면을 옮겨도 이 둘은 유지한다. 화면 고유 값(`version`, `view`, `item`, `run`, 필터)은 다른 화면으로 가면 지운다.
- 프로젝트를 바꾸면 작업을 비운다(그 프로젝트의 첫 작업을 고르거나 "모든 작업"). 이력·결과물은 "모든 작업"을 고를 수 있고, 작업실은 반드시 하나를 고른다.
- 필터는 목록 URL에 남긴다. 상세를 열고 닫거나 새로고침해도 유지된다. 결과가 0이면 "필터 모두 풀기"를 준다.
- 모바일에서 상세(결과물·이력·도구)는 전체 화면 `dialog`로 열고, 브라우저 뒤로 가기·Esc·툴바 뒤로가기로 닫힌다. 새로고침하면 같은 상세가 복원된다.
- 진행 중인 Run은 화면을 떠나도 서버에서 계속된다는 기존 Run 동작을 따른다. 작업실에 돌아오면 같은 Run 카드가 이어진다(Run 재개 동작은 기존 SSE+이벤트 로그 구조에 의존. 크리에이티브 Run에서의 동작은 확인 필요).

### 1.5 핵심 동선(한 흐름)

| # | 단계 | 화면 | 사용자가 보는 것 | 막힐 때 |
|---|---|---|---|---|
| 1 | 새 요청 | 작업실(빈 작업) | "무엇을 만들까요?" + 예시 칩. 명령어 안내 없음 | 연결·검증된 도구가 없으면 보내기 `aria-disabled` + 이유 문장 + 도구 탭 링크 |
| 2 | 파일 첨부 | 작업실 컴포저 | 첨부 칩마다 올리는 중·완료·실패·지원 안 됨 | 일부 실패면 "n개 중 m개만 올라갔어요" + 실패만 다시 올리기 / 빼고 계속 |
| 3 | 실행 | 작업실 스레드 | Run 카드: 단계·진행·자동 선택된 도구와 이유·멈추기 | 연결 끊김이면 "상태 확인 불가"(완료로 표시 안 함) + 다시 연결 |
| 4 | 미리보기 | 작업실 스테이지 | 현재 버전 이미지·상태·사용 도구 | 형식 미지원이면 상태 패널 + 원본 다운로드 + 원본 앱 열기 |
| 5 | 수정 | 작업실 컴포저 | "배경 어둡게" 같은 말로 요청 → v2 생성 | 실패하면 v1 그대로 + 어디서 멈췄는지 + 다시 시도 |
| 6 | 버전 비교 | 작업실 스테이지 | v1↔v2 나란히 / 겹쳐보기 + 변경 요약 | 비교할 버전이 없으면 버튼 숨김 |
| 7 | 승인·저장 | 승인 대화상자 | 승인 대상(파일·버전·시각·도구·해시) + 일어나는 일 3줄 | 연결 끊김이면 승인 비활성 + 이유 |
| 8 | 이전 버전 | 결과물 상세 | 버전 타임라인, 각 버전 보기·비교·받기 | 원본 사라짐이면 재편집 비활성 + 위치 다시 지정 |
| 9 | 재편집 | 결과물 상세 → 작업실 | "이 버전에서 재편집" → 새 버전(v3)이 생기고 이전 버전은 그대로 | 미리보기 없는 형식이면 원본 앱 열기 |

### 1.6 역할과 상태 목록

개인 앱이므로 사람 역할은 사용자 한 명이다. 화면에 영향을 주는 주체는 다음과 같다.

| 주체 | 설명 | 화면에서의 표시 |
|---|---|---|
| 사용자 | 요청·첨부·수정·승인·활성화 결정 | 파랑(사람의 행동) |
| 에이전트 | Claude/Luna 등. 도구를 고르고 실행 | 민트(에이전트의 존재). 사용한 에이전트 이름을 이력에 표시 |

| 실행 호스트 | Mac Studio | 연결 상태 표시줄 |
| 사용자 기기 | 폰·PC | 원본 앱 열기에서 "이 기기"로 구분 |

결과물 역할: **원본(source)** · **초안(draft)** · **최종 승인(approved)**. 버튼과 배지에 항상 단어를 쓴다.

## 2. U02 · 도구 관리

### 2.1 상태를 다섯 축으로 나눈다

사이트에 올라 있거나 등록돼 있다는 사실을 "연결 성공"처럼 보이지 않게 한다. 각 축은 따로 값과 근거를 가진다.

| 축 | 질문 | 값 | 근거 |
|---|---|---|---|
| 설치 | 앱이 실행 호스트에 있고 버전이 맞나 | 확인 안 됨 / 미설치 / 설치됨(버전) / 버전 불일치 | 호스트에서 버전 질의 |
| 연결 | 따까리가 앱과 실제로 통신하나 | 확인 안 됨 / 테스트 중 / 연결됨 / 끊김(마지막 응답 시각) | 연결 테스트 |
| 지원 | 확인된 기능이 있나 | 미검증 / 부분 지원(n/m) / 지원 / 지원 불가 | 기능 테스트(공식 소개 문구는 세지 않는다) |
| 활성 | 에이전트에게 보여 줄지 사용자가 정한 값 | 꺼짐 / 켜짐 / 켤 수 없음 | 사용자 결정 |
| 검증 | 마지막 직접 테스트 | 기록 없음 / 시각+통과·실패 / 오래됨 | 테스트 기록 |

핵심 규칙:

1. **모르는 것은 "미설치"가 아니라 "확인 안 됨"** 이다. 점선 테두리로 구분한다.
2. 활성화 스위치는 `설치=설치됨 ∧ 연결=연결됨 ∧ 지원이 미검증·불가가 아님 ∧ Mac Studio 연결 정상`일 때만 켤 수 있다. 아니면 `disabled`이고 **이유가 화면 문장**으로 있다(툴팁에만 두지 않는다).
3. 켜져 있어도 에이전트에게는 요청에 필요한 도구만 보인다. 13개를 상시 노출하지 않는다.
4. "오래됨" 기준 일수는 값이 없다. 정책으로 정해야 한다(확인 필요). 시안은 31일을 예로 쓴다.
5. 각 줄은 색 + 아이콘 + 단어를 같이 쓴다. 색만으로 상태를 말하지 않는다.

### 2.2 목록 행

이름·용도 · 요약 배지 하나 · 5축 칩. 요약 배지는 5축에서 계산한다(사용 가능 / 일부 기능만 / 점검 필요 / 버전 불일치 / 연결 끊김 / 테스트 중 / 검증 실패 / 설치 필요 / 후보·미검증). 요약이 "사용 가능"이 되려면 5축이 모두 정상이어야 한다. 헤더 요약줄은 "13개 · 사용 가능 0 · …"처럼 개수를 낸다.

### 2.3 상세

상태 5축(각각 의미 한 줄) → 활성화 스위치 + 이유 → 제공 기능과 제약(기능별 검증됨/지원 불가/미검증 + 제약 문구) → 테스트(연결·기능, 기록) → 설치·업데이트 안내 → 오류별 복구 안내 → 원본 편집기 열기 방식(U06).

## 3. U03 · 작업실

### 3.1 레이아웃

- 데스크톱: 왼쪽 스테이지(미리보기·버전·승인) + 오른쪽 스레드(요청·Run 카드, 560) + 스레드 아래 컴포저. 오른쪽 폭은 기존 `--tk-size-layout-workspace`.
- 모바일: 세로 한 열. 스테이지 → 스레드, 컴포저는 아래에 고정.
- 작업 목록 열을 따로 두지 않는다. 작업 선택은 문맥 줄의 선택 상자에서 한다(셸 사이드바가 이미 280이라 3열은 좁다).

### 3.2 입력

- 자연어. 슬래시 명령·도구 이름 입력을 요구하지 않는다. 입력창 안내는 "이렇게 말하면 돼요 · 예: 배경을 더 어둡게".
- 상황별 제안 칩("제목 색을 노랑으로", "v1에서 다시 해줘")은 눌러서 입력창을 채운다(바로 보내지 않는다).
- 한글 조합 중 Enter는 보내지 않고, 터치에서 Enter는 줄바꿈이다(디자인 시스템 규칙).
- 첨부는 클립. 칩마다 상태: 올리는 중(진행률) / 완료 / 실패(이유) / 지원 안 됨(이유).

### 3.3 도구 자동 선택의 투명성

- 스테이지 제목 아래에 "🔧 PhotoCraft 0.9.2 · 요청에 맞춰 자동 선택 · 왜 이 도구예요?".
- "왜 이 도구예요?"는 선택 근거, 후보와 제외 이유, "에이전트에게 보인 도구는 이 요청에 필요한 1개뿐"을 보여 준다. 도구 바꾸기는 켜져 있고 검증된 다른 도구가 있을 때만 가능하다.
- 쓸 수 있는 도구가 없으면 도구 줄 자체가 "지금 이 요청을 실행할 수 있는 도구가 없어요 · 도구 상태 보기"로 바뀐다.

### 3.4 진행·취소

- 진행은 Run 카드(기존 컴포넌트). 진행 퍼센트를 아는 렌더만 막대를 쓰고 모르면 단계만 쓴다(가짜 진행 막대 금지).
- 긴 렌더는 스테이지에 "v2를 만드는 중이에요 · 41% · 4:12 경과"와 현재 보이는 버전(v1)을 같이 둔다.
- 멈추기는 확인 대화상자를 거친다. 문구: "v2는 만들어지지 않아요. v1은 그대로 남고 임시 파일은 정리돼요". 취소 뒤에는 상태 패널("v2 만들기를 멈췄어요") + "같은 요청 다시 시도". 재시도 버튼은 누르는 즉시 `aria-busy`가 되어 중복 클릭을 막는다.
- "이 화면을 닫아도 Mac Studio에서 계속돼요"는 기존 Run 동작에 근거한 문구이나 크리에이티브 Run에서의 보장은 확인 필요.

### 3.5 미디어별 미리보기

기존 뷰어(`features/viewer/kinds.ts`의 `resolveViewMode`)가 이미지·PDF·표·코드·문서 변환 미리보기를 다룬다. 크리에이티브가 추가로 필요한 형식은 아래와 같고, 각 형식의 미리보기 방식은 아직 정해지지 않았다(확인 필요).

| 형식 | 현재 뷰어 | 필요한 것 | 시안의 상태 |
|---|---|---|---|
| 이미지 | 있음 | 버전 비교(나란히·겹쳐보기) | 구현 시안 |
| 영상 | 없음 | 포스터 프레임 + 렌더 진행 | "만드는 중 72%" 상태 패널 |
| 오디오 | 없음 | 파형·재생 | 결과물 상세 일반 패널 |
| CAD(dwg 등) | 없음 | 미리보기 불가 처리 | 상태 패널 + 원본 다운로드 + 원본 앱 열기 |
| 문서·표 | 있음 | 버전 비교 | 일반 패널 |

미리보기를 못 만들어도 **원본 다운로드는 항상** 있다(디자인 시스템 규칙). 미리보기 없이 승인하려면 체크 확인이 필요하고 기록에 "미리보기 없이 승인"이 남는다.

### 3.6 버전과 비교

- 버전 칩 `v1 v2`와 상태("승인 대기", "초안", "최종 승인"). 아직 없는 다음 버전은 점선 칩("만드는 중", "취소됨", "만들지 못함")으로 보인다.
- 비교: 나란히(각 칸 아래 버전·역할·시각) / 겹쳐보기(경계 슬라이더, 키보드로 조절). 변경 요약(바뀐 것·그대로인 것).
- 변경 요약의 출처(에이전트가 쓴 요약인지 실제 diff인지)는 정해지지 않았다(확인 필요). 시안은 사람이 읽는 3줄이다.

### 3.7 승인·저장 규칙

- 승인 대상은 영역 위에 고정해서 보인다: 파일 · 버전 · 생성 시각 · 도구 · 크기 · 해시 앞뒤.
- 대화상자: 제목은 질문형("v2를 최종 승인할까요?"), 대상 목록, 일어나는 일 3줄(보관함에 최종 승인으로 저장 / v1은 초안으로 남음 / 승인 취소 가능), 버튼 "취소"와 "v2 승인하고 저장". 승인 버튼은 누르면 `aria-busy`로 중복 클릭을 막는다.
- 승인은 최종 확정이 아니다. 새 버전을 만들면 v3이 생기고 v2는 그대로다. 승인 취소는 초안으로 돌리는 동작이다(이 동작이 데이터에서 가능한지 확인 필요).
- 승인 영역은 한 번에 하나만 보이고 primary 버튼은 승인 하나뿐이다(컴포저 보내기는 디자인 시스템 표준 둥근 아이콘).

### 3.8 오류 회복

| 상황 | 화면 |
|---|---|
| 도구 오류 | 상태 패널 "v2는 만들어지지 않았어요. v1은 그대로예요" + Run 카드 failed + 어디서 멈췄는지(파일·단계·오류 코드) + 다시 시도(n/3) · 원본 앱에서 열기 · 이력에서 보기 |
| 첨부 부분 성공 | §1.5-2 |
| 지원 불가 형식 | 첨부 칩 "이 요청에 쓸 도구 없음", 보내기에서 제외 안내 |
| 연결 끊김 | danger 배너 + Run 카드 "상태 확인 불가"(완료·실패로 단정하지 않음) + 승인·보내기 비활성 + 다시 연결 |
| 중복 클릭 | 모든 실행·승인·재시도 버튼은 즉시 `aria-busy` + `disabled` |
| 도구 없음 | 보내기 `aria-disabled` + 입력창 아래 이유 문장 |

### 3.9 원본 앱 이동(handoff)

직접 정밀 편집은 원본 앱에서 한다. 대화상자는 다음을 보인다(시안, 실제 왕복 미검증).

1. **어디서 열까**: Mac Studio 화면(원격 GUI) / 이 기기 / 이 화면 안(임베드). 선택할 수 없는 항목은 비활성이고 이유가 옆에 있다(이 기기에 앱 있는지 확인 안 됨, 임베드 미검증).
2. **흐름**: 복사본을 연다(원본 버전 보존) → 편집 중 → 저장 감지 → 새 버전(v3)으로 가져옴 → 작업실로 돌아와 v2↔v3 비교.
3. **실패**: 저장했는데 안 가져와짐(다시 가져오기·직접 올리기), 세션 끊김(편집 내용이 Mac Studio에 남아 있을 수 있음, 돌아와서 확인).
4. 주 버튼 "Mac Studio에서 열기"는 **지금 비활성**(실제 연결 없음).

저장 감지·가져오기 방식(파일 감시인지 명시적 가져오기인지)은 정해지지 않았다(확인 필요).

`compare`(기본) · `new` · `notools` · `attach` · `running` · `cancelled` · `v1` · `approved` · `error` · `lost` · `unsupported`, 추가로 `view=overlay`, 빈 프로젝트, 작업2(긴 렌더), 작업3(CAD).

## 4. U04 · 결과물 라이브러리

### 4.1 필요한 데이터(현재에는 없음)

현재 `ArtifactOut`에는 `run_id`, `session_id`, `sha256`, `source`, `area`, `preview_status`, `export_policy`, `retention_until`이 있다. 이 화면은 아래가 더 필요하다. **어떻게 저장할지는 정해지지 않았다**(후보 A: Artifact에 `lineage_id`·`version_no`·`role` 컬럼, 후보 B: 별도 버전 테이블. B앱 감사·계약 단계에서 결정. 확인 필요).

| 필요 | 지금 | 용도 |
|---|---|---|
| 같은 작업의 파일을 묶는 키(계보) | 없음 | 버전 묶기 |
| 버전 번호 | 없음 | v1·v2 표시 |
| 역할: 원본/초안/최종 승인 | 없음(`source`는 출처) | 역할 배지 |
| 입력 파일 ↔ 결과 연결과 원본 해시 | 없음(`sha256`만) | "원본이 바뀌었어요" 감지 |
| 프로젝트·작업 연결 | `session_id`/`workspace_id`(작업=세션) | 문맥 줄 |
| 만든 도구·버전 | 없음 | 도구 필터·표시 |

### 4.2 목록

- 한 행 = 한 작업의 결과(대표 버전). 대표 버전은 최종 승인이 있으면 그것, 없으면 최신.
- 행: 글리프 · 파일명(전체, 줄바꿈) · 작업 · 도구 · 크기 · 시각 · 역할 배지+버전 · 버전 수 · 승인 대기 · 해시 앞뒤.
- 같은 파일명은 **작업명·버전·해시**로 구분한다. 시안에 `thumbnail.png`가 서로 다른 작업에 2건 있다.
- 필터: 유형(이미지·영상·문서·오디오·CAD·벡터·표) · 역할 · 도구 · 검색. 필터는 URL에 남고 결과 수와 "필터 적용 중"을 알린다.
- 요약줄: "8개 · 최종 승인 2 · 승인 대기 1".

### 4.3 원본·최종 승인·초안 구분

색+아이콘+단어 배지: **원본**(파랑 정보), **초안**(amber), **최종 승인**(초록). 승인 대기는 초안 옆 amber 배지. 입력 파일은 상세 "원본·입력 파일"에 따로 둔다.

### 4.4 상세

미리보기 → 이름·배지 → 주 행동 "이 버전에서 재편집"과 "원본 다운로드" → 버전 타임라인(각 버전: 역할·시각·요약·크기·해시, 보기·직전 버전과 비교·받기) → 원본·입력 파일 → 정보(Artifact ID·프로젝트·작업과 옮기기·SHA-256·만든 실행 링크·보관).

### 4.5 예외 상태

## 5. U05 · 실행 이력

### 5.1 상태 어휘

기존 Run 상태 배지(완료·실패·실행 중)를 그대로 쓰고, 이력에서만 다음을 덧붙인다. 디자인 시스템에는 "부분 성공"·"산출물 없음"·"확인 필요" 상태가 없으므로 기존 `tk-badge--warning`과 `tk-policy[data-policy="blocked"]`로 표현했다. 정식 반영 전에 디자인 시스템 추가 요청이 필요하다(§7).

| 이력 표시 | 조건 | 완료로 세나 |
|---|---|---|
| 완료 | 종료 코드 정상 **이고** 산출물 등록 | 예 |
| 실패 | 단계 실패 | 아니오 |
| 부분 성공 | 일부 파일만 성공 | 아니오 |
| 정책 차단 | File Broker가 거절(정상 보호, 빨강이 아님) | 아니오 |
| 확인 필요(stderr만 출력) | 종료 코드 0, 산출물 없음, stderr만 | 아니오 |
| 산출물 없음 | 종료 코드 0, 산출물 0개 | 아니오 |
| 실행 중 | 진행 | — |

목록 요약줄은 "11건 · 문제 있음 7"처럼 문제 건수를 따로 낸다.

### 5.2 목록과 상세

- 목록: 날짜 그룹 → 행(제목 · 상태 배지 · 작업 · 시도 n/N · 도구와 버전 · 경과 · 시각). 문제 있는 행은 왼쪽 레일 색(실패 빨강, 경고 amber, 실행 중 민트).
- 필터: 상태(전체/문제 있음/진행 중/완료) · 도구 · 검색(작업·파일·오류 코드).
- 상세 순서: 제목·상태 → **오류 요약 콜아웃(어디서 멈췄나: 파일·단계·시도)** → 도구·에이전트·시간 → 단계 → 자원 사용 → 결과물 링크 → 안전한 재시도 → 로그.

### 5.3 안전한 재시도

- 재시도는 **새 시도(n+1)** 로 기록한다. 이전 시도·로그는 지우지 않는다.
- 원본 입력은 읽기 전용 복사본으로 연다는 전제를 문구로 밝힌다(구현 가능 여부 확인 필요).
- 성공한 실행을 다시 하면 덮어쓰지 않고 **새 버전**이 생긴다.
- 부분 성공은 "실패한 2개만 다시"를 준다. 이미 만든 결과는 건드리지 않는다.
- 정책 차단은 재시도 대신 "파일 다시 첨부"를 준다. 허용 범위 변경은 이 화면에서 못 한다(설정에서만).
- 재시도 버튼은 누르면 `aria-busy`로 중복 클릭을 막는다.

### 5.4 마스킹

- 로그의 키·토큰·홈 경로 일부는 `••••`로 가린 값을 **서버가 보낸다**. 화면은 가리는 표시(`.cw-mask`)만 한다. 화면이 가리는 것은 보안이 아니다(디자인 시스템 18 §3).
- 로그가 많으면 마지막 줄만 보이고 "전체 로그 12,481줄 보기"로 연다. 복사는 마스킹본이다.

|---|---|---|---|

## 6. U06 · 원본 편집기 임베드/별도 실행 UI 기획

**이 절은 UI 기획이다. 임베드·파일 왕복·CSP 같은 기술 항목은 하나도 실행하지 못했고 전부 미검증이다.** 편집기를 새로 만들지 않는다.

### 6.1 판정 분류

앱마다 아래 중 하나로 판정한다. 지금은 13개 모두 "판정 대기"다.

| 판정 | 뜻 | 채택 조건 |
|---|---|---|
| 임베드 | 이 화면 안에 iframe/WASM으로 연다 | 실제로 웹 빌드가 있고, 허용 출처 postMessage·파일 열기/저장 왕복·인증·세션 종료·모바일 반환이 모두 시험을 통과 |
| 별도 실행 · Mac Studio 화면 | 원격 GUI로 Mac Studio에서 연다 | 원격 GUI 경로가 검증되고, 모바일 사용성이 확인됨 |
| 별도 실행 · 이 기기 | 폰/PC에 설치된 앱으로 연다 | 이 기기에 앱이 있는지 감지 가능(확인 필요) |
| 불가 | 위 어느 것도 안 됨 | 원본 다운로드와 파일 직접 올리기만 |

### 6.2 화면에서의 구분

- "어디서 열까요?" 선택은 항상 **Mac Studio(실행 호스트)** 와 **이 기기**를 서로 다른 항목으로 보인다. 선택할 수 없는 항목은 비활성 + 이유 문장.
- 임베드는 판정이 나기 전까지 선택할 수 없다. 화면에 "미검증이라 선택할 수 없어요"를 보인다.
- 열기 방식 판정은 도구 상세의 "원본 편집기 열기 방식" 카드에 앱별로 보인다(시안은 3항목 모두 "미검증").

### 6.3 별도 실행의 돌아오기와 파일 동기화

§3.9의 흐름을 따른다. 필요한 상태: 준비 중 · 열림(대기) · 편집 중 · 저장 감지 · 가져옴 · 가져오기 실패 · 세션 끊김. 실패 때는 "다시 가져오기"·"파일 직접 올리기"·"돌아와서 확인하기"를 준다. 원본 버전은 항상 보존하고 편집 결과는 새 버전으로만 들어온다.

### 6.4 임베드 PoC에서 확인할 항목(실행하지 않음)

| 항목 | 확인 방법 | 지금 |
|---|---|---|
| 앱별 웹 빌드/WASM 존재 | 공식 릴리스·저장소 확인 | 미검증 |
| iframe 허용(CSP frame-ancestors, X-Frame-Options) | 응답 헤더 | 미검증 |
| COOP/COEP(SharedArrayBuffer 필요 앱) | 헤더·콘솔 | 미검증 |
| postMessage 허용 출처만, 임의 origin 차단 | 다른 origin에서 시도 | 미검증 |
| 파일 열기·저장 왕복(File Broker 경유) | 같은 파일로 열기→수정→저장→가져오기 | 미검증 |
| 인증·세션 만료·네트워크 종료 | 강제 종료·토큰 만료 | 미검증 |
| 모바일(390px) 반환·키보드 | 실기기 | 미검증 |
| 390px·데스크톱·라이트/다크·키보드·로딩/빈/오류·가로 넘침 | 계측 스크린샷·접근성 검사 | 시안만 검사(실제 임베드 화면 없음) |

### 6.5 접근성·시안 커버리지

핸드오프 대화상자와 도구 상세의 열기 방식 카드는 시안으로 있고, 390px·데스크톱 렌더와 이름 없는 버튼·중복 id 검사를 통과했다(`verification.md`). 임베드 상태(로딩·CSP 차단·origin 거부·세션 종료)의 실제 화면은 없다. 이 항목은 임베드 대상이 정해진 뒤 만든다.

## 7. 디자인 시스템 적용과 추가 요청

시안은 `ds/`에 디자인 시스템 산출물(`3599f2f`)을 그대로 복사해 쓴다. 제품 CSS 규칙(`.cw-*`)은 배치와 크기만 쓰고 색·간격·모서리·글자는 토큰만 쓴다. hex·임의 px·`!important` 없음.

디자인 시스템에 추가를 요청할 항목(부족한 부품은 직접 만들지 않는다는 규칙):

1. 이력 상태 3종: 부분 성공 · 확인 필요 · 산출물 없음(지금은 `tk-badge--warning` + 아이콘으로 대체).
2. 파일 형식 계열: video · audio · cad glyph 토큰(지금은 slide·doc·code 색을 빌려 씀).
3. 상태 5축 칩(`cw-axis`): 같은 모양이 여러 곳에서 필요하면 `tk-` 부품으로.
4. 버전 칩과 타임라인(`cw-ver`, `cw-timeline`).
5. 비교 슬라이더(겹쳐보기).

위 5개는 모두 이 시안에서 임시 `.cw-*`로 구현했다. 정식 이식 때 1~2가 받아들여지지 않으면 임시 클래스를 제품 CSS에 남긴다.

## 10. 잔여 선행과 게이트

원 WBS의 선행: U01은 A01·A02·D01, 다른 U는 D02·D04·D05·B14·A03 중 일부. PMS 요청 원문 UUID와의 대응은 확인하지 못했다. 이번 실행은 이 선행들이 끝났다는 증거를 받지 못했고 선행 상태를 바꾸지 않았다. 따라서:

- 남은 의존: 앱별 감사(A01), 계약(A02·D 계열), 도구 레지스트리·어댑터, 승인·버전 데이터 모델, 임베드 PoC, 실제 앱 연결 후 재계측.
- 시안 → 정식 전환 조건: 위 의존이 채워진 뒤 §9의 가정을 실제 값으로 바꾸고 `verification.md`의 검사를 실화면으로 다시 돈다.
