## 0. 이 문서의 지위

**정식 설계 확정본이 아니다. 선행 미충족 상태에서 만든 검토용 시안이다.**

- 선행 조사 결과(2026-10-15 22시 무렵, Luna): I1.4만 `done 100%`다. I1.1~I1.3은 부분 조사로 `doing 0%`, I2.1~I2.3은 `todo 0%`다(prerequisites.md §8). 이 개정은 그 조사에서 **시안에 필요한 사실과 상태 표기만** 반영했다. I3.1의 선행인 I2.2·I2.3이 아직 미완료이므로 I3.1·I3.2 완료 기준은 계속 미충족이다.
- I3.1의 선행은 I2.2와 I2.3, I3.2의 선행은 I3.1이다. 모두 미충족이므로 I3.1·I3.2의 완료 기준은 **미완료로 유지**한다. 시안이 있다는 이유로 done 처리하지 않는다.
- 시안의 호스트·서비스·수치·시각은 **전부 예시**다. 화면 맨 위에 "검토용 시안 · 값은 모두 예시이고 실제 상태가 아니에요" 띠를 고정했다. "도입 완료" 같은 상태는 어디에도 없다.
- 시안에서 가정으로 쓴 값은 화면 안에 `가정`/`예시` 딱지를 붙였다. 조사 값과 예시 값은 출처·관측 시각으로 분리했다(§1). I1/I2가 끝나면 §1의 가정을 실제 값으로 바꾼다.

## 2. I3.1 첫 화면 우선순위와 상세 진입 흐름

### 2.1 사용자가 첫 화면에서 답을 얻어야 하는 5개 질문 (제안)

| # | 질문 | 첫 화면의 답 | 화면 위치 |
|---|---|---|---|
| 1 | 지금 전체가 괜찮은가 | 전체 상태 한 단어(정상/주의/문제/미확인), 관측 범위, 마지막 시각 | 맨 위 상태 카드 |
| 2 | 어디가 문제인가 | 조치가 필요한 서비스·호스트 목록 (심각도 순, 같은 심각도는 오래 지속된 순) | 상태 카드 바로 아래 |
| 3 | 얼마나 심각하고 언제부터인가 | 심각도 배지, 유지 시간("12분째"), 영향 한 줄 | 목록 행 |
| 4 | 무엇을 먼저 확인하나 | 근거 한 줄, 다음 확인 1~2개 | 목록 행(근거) + 상세(다음 확인) |
| 5 | 더 보려면 어디로 가나 | 상세 화면의 확인한 값·판정 기록, 그 아래 Grafana/Dozzle 링크 | 상세 |

### 2.2 동선

`전체 상태 → 조치 필요한 항목 → (영향·근거) → 상세(다음 확인·확인한 값·판정 기록) → 외부 Grafana/Dozzle`

- 정상일 때는 상태 카드, "조치가 필요한 항목: 없어요", 호스트 3줄, 접힌 수집원·서비스만 남긴다. 모바일에서 한 화면 반 안에 끝난다.
- 외부 도구 링크는 상세 맨 아래에 두고 "더 자세히 보려면 · 선택"이라 적는다. 첫 화면에는 두지 않는다. 방문이 일상 점검의 필수 단계가 아니기 때문이다.
- 모바일은 목록 → 상세를 **화면 전환**으로 연다(뒤로가기 버튼, Esc, 목록 행으로 포커스 복귀). 데스크톱은 **왼쪽 목록 + 오른쪽 고정 상세**이고 첫 항목이 기본 선택된다.

### 2.3 일부러 뺀 항목과 이유

| 뺀 것 | 이유 |
|---|---|
| 코어별 CPU, 프로세스 상위 목록, 네트워크 속도 | 기존 `/resources`가 이미 담당한다. 일상 점검의 5개 질문과 무관하다 |
| 컨테이너 개수·목록 | 개수를 확정할 근거가 없다(미확인). Docker 소켓은 브라우저에 넘기지 않는다(I2.2 원칙) |
| 전체 로그 스트림 | Dozzle의 몫이다. 첫 화면은 판정 근거만 보인다 |
| 장기 추세 차트 | Grafana의 몫이다. 상세에서 링크로만 연결한다 |
| 자동 복구·재시작 버튼 | 현재 범위 제외. 상세에 "조치는 사람이 판단해요, 자동 조치를 하지 않아요"를 명시한다 |
| AI 분석 진입점 | I6 범위. 시안에 두지 않았다 |
| 이벤트 타임라인의 추정 사건 | 원천이 없으면 만들지 않는다. "판정 기록"은 수집 판정 규칙의 결과만 적고 그 사실을 딱지로 밝힌다 |

## 3. 상태 어휘와 판정 규칙 (I2.3 확정 전 제안)

| 상태 | 뜻 | 표시 |
|---|---|---|
| 정상 | 서비스 자체 health 원천이 있고 관측 범위에서 확인했으며 기준 안이다. **관측 범위와 확인 시각을 함께** 적는다 | 초록, 체크 |
| 주의 | **기준을 넘었다**(예: 디스크 사용률 초과가 유지됨). 확인하지 못한 것은 주의가 아니다 | 노랑, 삼각형 |
| 문제 | 서비스 응답 실패 같은 이상이 일정 시간 유지된 것을 확인했다. 단일 순간 값으로 확정하지 않는다 | 빨강, X 원 |
| 미확인 | 이 항목의 지금 상태를 알 수 없다. **장애가 아니다.** 이유를 항목마다 따로 적는다 | 회색, 물음표 + 사유 칩 |
| (전체만) 일부 미확인 | 확인한 범위에는 이상이 없고 확인하지 못한 범위가 있다. 장애·기준 초과가 아니라서 알림 색을 쓰지 않고 알림 대상도 아니다 | 회색, 물음표 |

- 상태는 **색 + 아이콘 + 글자**로 나타낸다. 색만으로 구분하지 않는다.
- **미확인의 사유는 서로 다른 것으로 표기한다.** `권한 없음`(Docker 읽기 거부), `확인 원천 없음`(서비스 응답을 판단할 수집이 없음), `연결 안 함`(win-server), `값 오래됨`(마지막 값이 허용치보다 오래됨), `갱신 실패`(관제 API 연결 실패, 화면 단위). 사유 하나로 모두를 "장애"로 묶지 않는다.
- 신선도는 상태와 **별개 축**이다. 마지막 값이 오래되면 항목이 마지막에 정상이었어도 지금은 "미확인"이고, "마지막으로 확인된 상태: 정상"을 따로 적는다. 허용치(5분)는 예시일 뿐 확정이 아니다.
- **전체 상태 우선순위: 문제 > 주의 > 일부 미확인 > 정상.** 이전 안은 "일부 확인 불가면 전체 주의"였으나 노랑 주의가 기준 초과와 확인 불가를 섞어 장애처럼 읽히게 해서 바꿨다. 확인하지 못한 범위는 여전히 **정상으로 세지 않는다**.
- 정상 오표시를 막는 조건: 서비스 응답 원천이 없으면 서비스는 정상으로 쓰지 않는다. 수집 대상 `up`, `/ready` 200, Grafana 200은 "응답"이고 "정상"이 아니다. 수집원 행 배지는 정상 대신 **응답**이라고 쓴다.
- 빈 조회(series 0)는 0도 정상도 아니다. 미수집·미지원·실제 0을 구분할 수 없으면 정상 판정에서 제외하고 그 이유를 근거 행에 적는다.
- 조사 값(21:59~22:00 KST 표본)은 관측 시각을 붙여 표시하고 실시간 연결처럼 표현하지 않는다. 80/90%, 일일 보고서 기준도 서비스 전체 상태 기준으로 확대하지 않는다.

- 1024px 이상에서만 2열이다(디자인 시스템 `lg` 기준과 같다).

## 5. 접근성 검토와 실브라우저 검증

검증 환경: Google Chrome 155.0.8059.79 headless(CDP), 모바일 390×844 DPR 2, 데스크톱 1280×900, 라이트/다크. Playwright가 설치돼 있지 않고 도구 설치가 금지돼 있어 `scripts/verify.mjs`가 설치된 Chrome을 직접 제어한다.

## 6. 남은 게이트 (I3 원래 완료 조건은 미충족)

| 게이트 | 상태 | 풀려야 할 것 |
|---|---|---|
| I3.1 선행 I2.2, I2.3 | 미충족 | I1.1~I1.3 남은 조사(Docker 읽기 권한, win-server 연결, host ID 매핑, Grafana/Dozzle 접근) → I2.1 매핑 → I2.2 연동 결정 → I2.3 상태 기준. I1.4는 done |
| I3.1 완료 기준 | 미충족 | 5개 질문 확정, 정상 시 필수 정보와 제외 근거를 실제 데이터 구조로 재검증 |
| I3.2 선행 I3.1 | 미충족 | 위 항목 |
| I3.2 완료 기준 | 부분 | 8상태 시각 설계·접근성 점검은 시안으로 수행. 실제 수집원·임계값·링크 반영과 사용자 확인 필요 |
| I3.3 | 미착수 | 정상/단일 서비스/호스트 문제/수집 실패/회복 시나리오의 정답 확정 |

남은 권한·확정 불가: Docker 읽기 권한(별도 결정), 서비스 health 원천, 임계값·유지시간, win-server 연결 경로, canonical host ID, 5개 질문의 사용자 원문. 어느 것도 이번에 결정하거나 가정을 확정으로 올리지 않았다.

사용자가 다음에 판단할 것: ① 시안의 방향(상태 카드 + 조치 목록 + 접힌 정상 항목)이 맞는지 ② 전체 상태를 "일부 미확인"(중립색, 장애 아님)으로 나누는 규칙 ③ 링크를 첫 화면에서 뺀 것.
