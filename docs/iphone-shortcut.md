# 아이폰 공유 시트에서 따까리로 파일 보내기

단축어의 **URL 콘텐츠 가져오기 → POST → 요청 본문 → 파일**을 사용한다. 파일 한 개의 바이트를 본문 전체로 보내며, 파일명은 URL에 넣는다. 양식 안에서 파일 필드 유형을 고르는 과정은 없다. [Apple 공식 설명](https://support.apple.com/ko-kr/guide/shortcuts/apd58d46713f/ios)은 POST의 요청 본문으로 JSON·양식·파일을 지원한다고 명시한다.

이 절차는 `/api/transfers/raw`가 배포된 서버를 전제로 한다. 공식 지원 여부와 서버 통합 테스트를 확인했으며, 실제 아이폰에서 공유 시트를 실행한 검증은 별도로 필요하다.

## 단축어 만들기

1. 따까리 **설정 → 아이폰 단축어 → 토큰 만들기**를 누르고 새 토큰을 복사한다. 기존 단축어에 보관한 업로드 토큰도 유효하다면 재사용할 수 있다.
2. 아이폰 **단축어** 앱에서 `+`를 눌러 이름을 **따까리로 보내기**로 정한다.
3. 단축어의 세부사항에서 **공유 시트에 보기**를 켠다. 편집기 맨 위의 공유 시트 입력 유형에서 **이미지·미디어·파일**을 선택한다. 사진 앱은 이미지, 파일 앱의 PDF·문서는 파일로 받는다. iOS 버전에 따라 세부사항을 여는 버튼 위치는 다를 수 있다.
4. **각 항목 반복** 동작을 추가한다. 반복할 목록에 **단축어 입력** 변수를 선택한다. 아래 5~9번 동작을 전부 **반복 종료** 위에 둔다. 한 장도 이 반복으로 처리된다.
5. **이름 가져오기** 동작을 추가한다. 입력을 **반복 항목**으로 선택한다. 이름에는 `.pdf`, `.heic`, `.jpg` 같은 확장자가 포함되어야 한다. 이름 없이 들어오는 항목은 파일 앱에 저장한 뒤 공유한다.
6. **URL 인코딩** 동작을 추가한다. 인코딩할 입력으로 5번의 **이름** 출력을 선택한다. URL 전체가 아니라 파일명만 인코딩한다. 한글·공백·`&`·`+`·`#`가 들어간 이름도 이 과정을 거친다.
7. **URL** 동작을 추가하고 다음 텍스트를 붙여 넣는다.

   ```text
   https://ttakkari-api.winterholic.net/api/transfers/raw?filename=
   ```

   `filename=` 바로 뒤에 6번의 **URL 인코딩된 텍스트** 변수를 삽입한다. 입력 칸에서 **변수 선택**으로 파란 변수 토큰을 넣는다. `반복 항목`이나 `URL 인코딩된 텍스트`라는 글자를 직접 타이핑하면 변수로 연결되지 않는다.
8. **URL 콘텐츠 가져오기** 동작을 추가하고 다음과 같이 설정한다.

   | 항목 | 값 |
   |---|---|
   | URL | 7번 URL 동작의 출력 변수 |
   | 방법 | `POST` |
   | 요청 본문 | **파일** |
   | 파일 | **반복 항목** 변수 |
   | 헤더 `Authorization` | `Bearer ` 뒤에 복사한 업로드 토큰 |
   | 헤더 `Content-Type` | `application/octet-stream` |

   **요청 본문 메뉴 자체를 눌러 파일로 바꾸면 파일을 넣는 칸이 나타난다.** 텍스트·숫자·배열·사전·불리언만 나오는 목록은 파일 본문을 고르는 메뉴가 아니다. 그 목록을 닫고 동작의 요청 본문 선택으로 돌아간다. `files`라는 양식 필드는 추가하지 않는다.

   파일 값은 반드시 **반복 항목**으로 다시 선택한다. 자동으로 직전 동작의 URL이나 인코딩된 이름이 선택되어 있으면 파일 바이트가 전송되지 않는다.
9. 처음에는 **훑어보기** 동작을 추가하고 8번 **URL 콘텐츠** 출력을 선택한다. 응답의 `files`에 파일 이름·크기·저장 경로가 들어 있으면 서버에 저장된 것이다.

```text
공유 시트에서 이미지·미디어·파일 받기
각 항목 반복 [단축어 입력]
    이름 가져오기 [반복 항목]
    URL 인코딩 [이름]
    URL [고정 주소?filename= + 인코딩된 이름 변수]
    URL 콘텐츠 가져오기 [URL]
        POST / 요청 본문: 파일 / 파일: 반복 항목
        Authorization: Bearer 업로드토큰
        Content-Type: application/octet-stream
    훑어보기 [URL 콘텐츠]
반복 종료
```

## 실행과 성공 확인

사진 앱에서 사진을 선택하거나 파일 앱에서 파일을 선택해 **공유 → 따까리로 보내기**를 실행한다. 첫 실행 시 네트워크·파일 접근 허용 팝업이 나올 수 있다. 여러 항목을 선택하면 순서대로 요청한다.

서버의 정상 응답 예시(파일명·크기·ID는 입력에 따라 달라진다):

```json
{
  "files": [{
    "path": "/Users/winterholic/.ttakkari/inbox/보고서.pdf",
    "name": "보고서.pdf",
    "size": 12345,
    "artifact_id": "..."
  }],
  "notes": []
}
```

기본 저장 위치는 `~/.ttakkari/inbox`이며 서버 설정으로 바꿀 수 있다. 기존 처리와 동일하게 HEIC는 기본 JPG 변환, 사진 위치 정보는 기본 제거, 같은 파일명은 번호를 붙여 저장한다. 일반 문서는 바이트를 그대로 저장한다. 업로드 토큰은 다른 API의 로그인 권한을 주지 않는다.

훑어보기 대신 알림을 원하면, 반복 안에서 **사전 값 가져오기**로 `files`를 읽고 **조건문**으로 값이 있는지 확인한 다음 성공 분기에 **알림 보기**를 넣는다. 오류 응답을 성공 알림으로 바꾸지 않는다. 실패 분기에서는 원래 URL 콘텐츠를 훑어보기로 확인하고 단축어를 중단한다.

## 오류를 구분하기

| 결과 | 확인할 항목 |
|---|---|
| `405 Method Not Allowed` | 새 raw API가 아직 서버에 적용되지 않았는지 확인 |
| `401` | Authorization의 `Bearer` 뒤 공백, 토큰 누락·폐기 여부 |
| `422` | URL의 `filename=` 뒤에 이름 변수가 연결되었는지 확인 |
| `415 wrong_body_type` | 요청 본문을 파일로 선택하고 Content-Type을 위 표대로 지정 |
| `413 too_large` | 서버나 외부 접속 경로의 크기 제한. 앱의 파일 → 보내기로 전환 |
| 이름만 들어 있는 작은 파일이 저장됨 | 파일 값에 인코딩된 이름·URL 대신 반복 항목을 연결 |

단축어의 파일 본문 요청은 한 파일 전체를 전송한다. 중간에 끊기면 해당 파일을 처음부터 다시 보낸다. 여러 파일 중 앞선 파일이 이미 저장된 경우 재실행 시 같은 이름에 번호가 붙을 수 있다. 큰 파일·동영상이나 불안정한 연결에서는 앱의 **파일 → 보내기**가 조각 업로드와 이어 올리기를 지원한다.

## 요청 형식과 검증 범위

새 API는 `POST /api/transfers/raw?filename=<URL 인코딩된 이름>`이다. 선택 쿼리는 `dest_dir`, `convert_heic`, `strip_location`, `keep_original`이다. 앱의 기존 조각 업로드와 스크립트용 multipart `/api/transfers/simple`은 유지한다.

서버 통합 테스트는 업로드 토큰·폐기·다른 API 접근 거절, 인코딩된 한글·기호 파일명, PDF 바이트 보존, HEIC 변환·GPS 제거, 원본 보존 옵션, 빈 파일, 같은 이름 반복, 권한 밖 폴더 거절, 잘못된 본문 모드 거절, 크기 초과·전송 중단 시 임시 파일 정리를 확인한다. 아이폰 UI의 파일 본문 옵션은 Apple 공식 문서에 근거한다. 실제 아이폰 공유 시트에서 선택·변환·네트워크 전송까지 실행한 결과로 확대 해석하지 않는다.
