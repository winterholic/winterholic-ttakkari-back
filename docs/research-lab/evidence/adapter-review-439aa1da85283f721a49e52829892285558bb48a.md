## 테스트 계약 강제력

- `tests/test_research_adapters.py:376-403`은 실제 `HostGpu.stop` 시그니처를 introspect한 뒤, 구현 호출부는 일반 `MagicMock`으로 대체한다. `autospec/spec`은 없지만 `strict_stop(*args, **kwargs)` side effect가 인자 전달을 직접 거부하므로 잘못된 keyword/positional 호출은 검출한다. 이는 호출 형태 검사이지, 실제 HostGpu instance ownership이나 stop의 실효성 검사는 아니다.
- `tests/test_research_adapters.py:480-529`도 실제 `run_worker` 시그니처를 introspect하고, mock side effect 함수가 예상 인자 형식으로 호출되게 강제한다. `spec`은 없으나 잘못된 호출 인자는 Python side effect binding 단계에서 실패한다. 다만 stub은 `{"text": ...}`만 반환하고 측정값의 숫자나 인식 문자열을 단언하지 않는다.
- STT 실패 검사는 모든 호출이 실패하는 경우만 다룬다 (`:540-544`). 한 chunk 성공·한 chunk 실패 혼합 사례는 없어서 현재 부분 실패의 `succeeded` 상태가 누락되어 있다.
- Retrieval 새 테스트(`:587-628`)는 설정 echo만 확인하므로 실제 계산에서 weight나 normalization이 결과를 바꾸는지 검증하지 않는다. 구현은 소스상 소비된다.
- HostGpu cleanup mock은 무인자 호출과 cleanup metadata를 검사하지만 다른 launch ID를 보호하는지, 반환된 stop 결과가 실제 stopped인지 확인하지 않는다 (`:380-420`). TTS 실행 중 취소 경쟁 테스트도 없다.

## 재현 절차

1. **결함 1 소유권/성공 오표시:** 단위 재현에서는 mock `HostGpu.start()`가 launch A를 반환한 뒤 `bench()` 시점에 active state를 launch B로 교체하고, finally의 `stop()` 호출이 B를 대상으로 하는지 단언한다. 실제 코드 대조는 `host_gpu.py:831-848`의 무인자 `stop()`이 `_current()`를 다시 읽는 것으로 성립한다. 별도로 `stop()`이 lock 해제 없이 timeout return한 결과를 돌려주고 adapter가 `cleanup.success=True`로 기록하는 경우를 단언한다.
2. **결함 2 부분 STT 실패:** `synthesize_and_stt`에서 합성 결과 chunk 2개를 주고 `run_worker` 첫 호출은 `{"text": "..."}`, 두 번째 호출은 예외를 내게 한다. 현재 코드는 1/2 `stt_error`를 기록하고도 `status="succeeded"`로 반환한다 (`tts_synthesis.py:544-606`).
3. **결함 6 취소:** `_execution_lock`을 테스트에서 선점한 채 adapter가 대기하게 한 후 `cancel_event.set()`, lock을 해제한다. 현재 코드는 합성을 호출한다. 또는 `provider.synthesize()`를 block시키고 합성 도중 event를 set해도 호출 취소/중단이 전파되지 않는다.
4. **결함 4·7 파라미터 목록:** LLM의 `supported_parameters`에 `main_gpu`, `quant_method`가 있지만 같은 key를 `validate_config`가 거부함을 조회한다. TTS의 `split_on_comma`, `total_steps`도 같은 모순을 보인다. LLM `quant_type="Q2K"`는 현재 오류 없이 통과한다.
