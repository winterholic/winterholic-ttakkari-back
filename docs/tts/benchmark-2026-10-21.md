- **하드웨어/OS**: Mac Studio (Apple Silicon arm64, macOS)
- **TTS 엔진**: Supertonic 3 (`v1.7.3`, ONNX Runtime `1.31.0`, diffusion steps `8`, CPU threads `4`)
- **TTS 모델 경로**: `back/.tts-runtime/supertonic/assets` (ONNX 가중치 + 음성 스타일 `M1`~`M10`, `F1`~`F10`)
- **STT 엔진**: `faster-whisper-large-v3` (`CTranslate2 4.8.3`, robust 프로파일, CPU threads `4`)
- **측정 방식**: 워커 프로세스 cold/warm 시작부터 종료까지 부모 벽시계(`parent_wall_seconds`), 자식 로드(`load_seconds`), 첫 청크 지연(`ttfa_seconds`), 합성 시간, 오디오 길이, RTF, 피크 RSS(`peak_rss_bytes`), 동시 실행 시 양쪽 시작·종료 epoch 및 겹침 시간(`overlap_seconds`)을 기록. 모든 대푯값은 5회 시행의 중앙값(median).

- **TTFA (Time to First Audio)**: 첫 번째 청크 생성까지 0.70~1.03초 내에 완료되어, 스트리밍 청크 재생 시 사용자가 1초 이내에 첫 소리를 들을 수 있음.
- **RTF (Real-Time Factor)**: 0.17~0.19로, 1초 분량 음성을 합성하는 데 약 0.17~0.19초만 소요됨(실시간 대비 약 5.3~5.9배 빠름).
- **메모리(RSS)**: 프로세스당 피크 RSS가 550~610 MB 수준으로 유지되며, 일회용 프로세스 종료 시 완전히 반환됨.

## 4. TTS + STT 동시 실행 간섭 및 저하율 (n=5)

동일 시점에 TTS(중문 194자, 29.58초 분량)와 STT(35.60초 음성 전사)를 병렬 실행하여 자원 경합 및 저하율을 실측했습니다.

| 시행 | 겹침 구간 (Overlap) | TTS 벽시계 | STT 벽시계 |
|---|---:|---:|---:|
| Trial 1 | 7.89초 | 7.90초 | 26.71초 |
| Trial 2 | 6.78초 | 6.78초 | 26.18초 |
| Trial 3 | 5.81초 | 5.81초 | 25.59초 |
| Trial 4 | 6.14초 | 6.15초 | 26.31초 |
| Trial 5 | 5.66초 | 5.66초 | 25.00초 |
| **중앙값** | **6.14초** | **6.15초** | **26.18초** |

### 저하율 계산 및 분석

1. **TTS 저하율**:
   - 단독 중앙값: 5.5043초
   - 동시 실행 중앙값: 6.1476초
   - **계산된 저하율**: `(6.1476 - 5.5043) / 5.5043 = +11.69%`
2. **STT 저하율**:
   - 단독 중앙값: 25.2783초
   - 동시 실행 중앙값: 26.1759초
   - **계산된 저하율**: `(26.1759 - 25.2783) / 25.2783 = +3.55%`
3. **겹침 구간 검증**:
   - 양쪽 태스크의 시작/종료 epoch 비교를 통해 매 시행마다 5.66초~7.89초(중앙값 6.14초)의 실질적인 CPU 경합이 발생했음을 수학적으로 증명함 (`overlap > 0`).
   - 과거 설계 검토 시 언급되었던 '0% 저하율'(하드코딩된 수치)은 허구이며, 실제로는 CPU 스레드 경합으로 인해 TTS 약 11.7%, STT 약 3.6%의 완만한 지연이 발생함.
4. **자원 안정성**:
   - 동시 실행 시 피크 메모리는 TTS 약 0.58 GB + STT 약 3.79 GB = 합계 약 4.37 GB로, 호스트의 가용 메모리 한도 내에서 안전하게 격리되어 공존 가능함을 확인.
   - 따라서 STT 큐와 TTS 큐를 통합하거나 상호 배타적으로 잠그지 않고, **독립 직렬 큐(`work-tts.lock`)를 유지하는 설계**가 타당함을 실측으로 입증함.
