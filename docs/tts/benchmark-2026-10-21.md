## 1. 측정 환경

- **하드웨어/OS**: Mac Studio (Apple Silicon arm64, macOS)
- **TTS 엔진**: Supertonic 3 (`v1.7.3`, ONNX Runtime `1.31.0`, diffusion steps `8`, CPU threads `4`)
- **TTS 모델 경로**: `back/.tts-runtime/supertonic/assets` (ONNX 가중치 + 음성 스타일 `M1`~`M10`, `F1`~`F10`)
- **STT 엔진**: `faster-whisper-large-v3` (`CTranslate2 4.8.3`, robust 프로파일, CPU threads `4`)
- **측정 방식**: 원자료의 `parent_wall_seconds`, 워커 내부 `ttfa_seconds`, 합성 시간, 오디오 길이, RTF, 자식 프로세스별 피크 RSS(`peak_rss_bytes`)를 기록. 아래 시간 중앙값은 각 5회 시행의 중앙값이다. 원자료에는 benchmark 실행 스크립트·로그, 전체 입력 본문, 캐시 상태가 포함되지 않아 이 자료만으로 입력 정규화 전후의 글자 수 측정 시점과 재현 절차는 확인할 수 없다.

## 2. TTS 단독 실행 (단문 / 중문 / 장문, n=5)

| 텍스트 구분 | 원자료 `text_chars` | 청크 수 | 생성 오디오 | 로드 지연 p50 | 워커 내부 TTFA p50 (범위) | 부모 작업 벽시계 p50 (범위) | RTF p50 | 자식 피크 RSS p50 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| **단문 (short)** | 28 | 2개 | 5.55초 | 0.33초 | 0.71초 (0.67–2.24초) | 1.47초 (1.43–5.39초) | 0.19 | 549.2 MB |
| **중문 (mid)** | 178 | 5개 | 29.58초 | 0.33초 | 0.70초 (0.67–0.74초) | 5.50초 (5.46–5.75초) | 0.17 | 579.4 MB |
| **장문 (long)** | 556 | 16개 | 91.75초 | 0.32초 | 1.03초 (0.95–5.09초) | 15.72초 (15.62–43.42초) | 0.17 | 606.8 MB |

- `text_chars`는 원자료에 기록된 수치 그대로다. 이전 본문의 중문 194자·장문 537자는 raw 값 178·556과 달라 raw 기준 값으로 바로잡았다. 입력 원문과 계측 스크립트가 없어 raw 글자 수가 정규화 전인지 후인지는 확인할 수 없다.
- **TTFA (Time to First Audio)**는 자식 워커 내부에서 첫 청크를 만든 시점이다. 부모 요청의 결과 완료와 브라우저 재생 가능 시점은 별도이며, API 접수부터 사용자가 실제로 듣기까지의 시간은 측정하지 않았다. 따라서 1초 이내 첫 소리 또는 8초 사용자 지연 조건의 충족 여부는 미검증이다.
- 부모 작업 벽시계 p50은 `parent_wall_seconds` 기준이다. 단문 첫 두 시행은 5.3914초·2.1998초, 장문 마지막 두 시행은 43.4171초·33.7485초였다. 중앙값만으로는 이 변동을 설명하지 못하므로 표에 범위를 함께 적었다.
- **RTF (Real-Time Factor)**: 0.17~0.19로, 1초 분량 음성을 합성하는 데 약 0.17~0.19초만 소요됨(실시간 대비 약 5.3~5.9배 빠름).
- **메모리(RSS)**: 개별 자식 프로세스의 관측 피크 중앙값이다. OS가 종료 후 회수하는 동작이나 호스트 전체 가용 메모리·swap은 이 자료에서 측정하지 않았다.

| 시행 | 부모 작업 epoch 겹침 | TTS 부모 작업 벽시계 | STT 부모 작업 벽시계 |
|---|---:|---:|---:|
| Trial 1 | 7.89초 | 7.90초 | 26.71초 |
| Trial 2 | 6.78초 | 6.78초 | 26.18초 |
| Trial 3 | 5.81초 | 5.81초 | 25.59초 |

| Trial 5 | 5.66초 | 5.66초 | 25.00초 |

### 저하율 계산 및 분석

1. **TTS 저하율**:
   - 단독 중앙값: 5.5043초
   - 동시 실행 중앙값: 6.1476초
   - raw 중앙값 산술: `(6.1476 - 5.5043) / 5.5043 = +11.69%`. 이 값은 이 데이터 조건의 산술 재현값이다.
2. **STT 저하율**:
   - 단독 중앙값: 25.2783초
   - 동시 실행 중앙값: 26.1759초
   - raw 중앙값 산술: `(26.1759 - 25.2783) / 25.2783 = +3.55%`. 이 값은 이 데이터 조건의 산술 재현값이다.
3. **겹침 구간 검증**:
   - 원자료의 시작·종료 epoch는 부모 작업 구간의 겹침(5.66~7.89초, p50 6.14초)을 보여준다. 자식 추론 구간별 시작·종료 시각은 없어 추론 자체의 동시 실행이나 CPU 경합 원인을 증명하지 않는다.
4. **메모리 한계**:
   - 동시 시행에 기록된 TTS·STT RSS는 서로 다른 자식 프로세스의 개별 피크다. 두 수치의 합은 동일 시점 호스트 피크가 아니며, 호스트 메모리 여유·swap 추적도 없다. 이 벤치로 안전한 공존이나 동시 실행의 최적성을 확정하지 않는다.
   - 이 원자료만으로는 큐 통합·상호 배타 실행·독립 큐 중 어느 정책이 더 타당한지 판정할 수 없다. `allow_concurrent`는 현재 설정값이며 자원 안전성 검증 결과로 해석하지 않는다.

### 계측 provenance 한계

저장소에는 이 raw를 만든 실행 스크립트와 실행 로그가 없다. raw에는 `text_chars` 수치와 metric 값이 있지만 전체 입력 텍스트, 정규화 전후의 측정 지점, 캐시 조건, 실행 명령을 연결할 정보가 없다. 값과 중앙값은 보존된 raw에서 재계산했으며, 누락된 provenance를 추정하거나 raw를 수정하지 않았다.
