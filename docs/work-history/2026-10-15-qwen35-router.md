# 2026-10-15 Qwen3.5-9B 접수 라우터 실험

## 결정

- 사용자의 명시적 지시로 Qwen3.5-9B Q4_K_M의 격리 실험을 수행했다. 운영 Luna/Haiku 경로는 변경·배포·재시작하지 않았다.
- 현 시점 판정은 **대체 불가**다. 작은 합성 pilot만으로 정확성을 인정할 수 없고 CPU p95 10.51초가 과거 Haiku 전체 중앙값 7.36초를 초과했다. 실제 정정 데이터셋, 쌍대 baseline, live shadow, GPU 성능 측정이 남았다.
- 실험 엔진은 llama.cpp b11655를 골랐다. 공식 MLX-LM 소스에 Qwen3.5 모델 지원은 확인했으나, 공식 server에서 같은 JSON Schema constrained decoding을 확인하지 못했다. 이 실험에서 MLX 추론은 실행하지 않았다.

## 작업

- ADR 0013 desk 정책과 과거 평가를 검토하고, 모델 출력 확인 전에 평가 게이트를 `experiments/qwen35-router/evaluation-plan.md`에 기록했다.
- isolated `src/ttakkari/experiments/qwen35_shadow.py`에 후보 snapshot별 JSON Schema, llama.cpp constrained decoding, strict Pydantic 검증, 후보 membership 검사, loopback 제한, bounded nonblocking queue를 작성했다. 운영 desk에는 연결하지 않았다.
- 모델: `lmstudio-community/Qwen3.5-9B-GGUF` Q4_K_M, revision `d9006465af6fc714af653e381fbfa55ead5af84b`, SHA256 `cd76ec205963b3b33350093e6904d9de16c4e666fd104e1f632d25c7f15f2a13`.
- llama.cpp Metal 초기화는 `failed to create command queue`로 실패했다. 격리된 CPU 실행은 모델 로드 약 36초, 생성 약 15.3 token/s, 응답 RSS 스냅샷 약 10.5GB, 전체 메모리 가용 약 36.0GB·pressure normal을 보였다.
- synthetic 3유형을 3회씩 순차 재생: schema/validator 9/9, 정책 라벨 9/9, pass³ 3/3, p50 5.924초, p95 10.514초. 한 semantic mismatch probe는 validator가 거부했고 강제 교정하지 않았다. 별도의 초기 empty enum schema 오류는 schema를 수정했다.
- production feedback 원문을 열거나 복사하지 않았다. 안전한 local redaction/export path를 확보하지 못해 실데이터셋은 미작성.

## 남은 작업

- QWEN04: 승인된 정책 정정 사례만 local에서 비식별화하고 사람 검토로 라벨 확정.
- QWEN05: Luna/Haiku paired replay, 공격·긴 입력·후보 변화, 실제 비용/peak 자원 및 충분한 반복 측정.
- live shadow는 기본 opt-in과 queue backpressure를 운영에 붙이고 검증할 배포 절차가 마련될 때까지 미실행.

실험 기준, 합성 결과, 사용자 HTML 보고서는 Ttakkari outbox에 별도로 보관했다. 공유 backend에는 기존의 다른 dirty 변경이 남아 있어 commit하지 않았다.

## 2026-10-15 후속 정정·실데이터 export

- 이전의 **“대체 불가”** 결론은 철회하고 **“대체 근거 부족, 운영 교체 보류”**로 정정한다. CPU pilot p95 10.514초와 다른 시점·다른 합성 입력의 Haiku 중앙값 7.36초는 서로 다른 통계량/분포라 성능 우열 근거가 아니다. 같은 비식별 입력·분포·조건에서 통계량을 맞춘 paired replay 후에만 우열을 말한다. 이전 보고서를 삭제하지 않고 개선본과 이 정정 기록을 남겼다.
- prompt tuning 전 semantic probe는 post-tuning 합성 pilot과 분리했다. 보존된 probe 출력 1건은 answer와 lead_id를 동시에 내어 validator가 거부했다(관찰 출력 기준 1/1; 전체 사전 탐색 시도 분모는 기록이 불완전해 추정하지 않음). 초기 empty-candidate schema 거부 1건은 생성 전 실패라 별도 기록한다. post-tuning 합성 pilot 9/9는 해당 pilot 내부 결과만 표현한다.
- 로컬 PostgreSQL `desk_feedback`를 read-only transaction으로 조회했다. 내용 출력 없이 먼저 집계: 1건(answer→answer 사용자 확인), 교정 0건. `qwen35_feedback_export.py`는 message/decided/expected만 읽고 note·UUID를 제외하며 민감 패턴을 제거/검사하고 mode 0600으로 atomic write한다. export 1건은 `user_confirmation_reference_only`로 분류, 민감 패턴 negative scan 통과 및 마스킹 후 직접 검토를 마쳤다. 실제 교정 정답 분모는 0이다. 원문은 외부에 전송하거나 command output으로 노출하지 않았다.
- 저장된 것은 원 메시지뿐이며 당시 접수 prompt에 포함된 작업판·최근 대화 전체 snapshot은 없다. 따라서 유일한 confirmation export는 동일 입력 paired replay 대상이 아니고 정답률에도 넣지 않는다.
- shadow 검증 추가: mutable 후보 입력의 snapshot 동결, empty candidate schema, answer+lead mismatch, timeout/unavailable 예외 전파, nonblocking queue pressure. 실험 전용 테스트 14개와 ruff 검사 결과를 이번 기록에 새로 확인한다. 운영 desk 연결/배포/재시작/live shadow는 하지 않았다.
- 당시 callable tool 목록에 `account_usage` 및 `message_worker`가 노출되지 않았다. fresh baseline cap을 확인하지 못해 Luna/Haiku API paired replay를 실행하지 않았고, 지정 35B worker에게 재현 정보를 전달하지 못했다. 직접 Metal/MLX 진단은 중복 수행하지 않았다. 해당 worker 재현 요청의 미전달은 blocker로 남긴다.
- MLX/Metal 실측이 미완료이므로 WBS 2.1.5.2를 `doing`으로 되돌렸다. 실데이터 export는 방법 검증과 확인 사례 1건만 있어 WBS 2.1.5.4도 `doing`; 최종 판정 WBS 2.1.5.6 역시 `doing`이다. 전체 실험 요청을 완료로 표시하지 않는다.
