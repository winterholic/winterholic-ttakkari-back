## Findings and changes

- **Identity and alias bypass:** `persist_extracted_knowledge` directly inserted candidate entities and every proposed alias before linking. Its fallback `_ensure_entity` also created claim/relation endpoints without requiring a verified mention. A caller supplied `alias_source="seed"` was accepted as alias provenance. Persistence now creates entity identities only through `resolve_entity` with a passage and an evidence row that matches the exact mention slice. An entity candidate without an anchored mention is dropped. Claim/relation endpoints get an identity anchor only when their exact label is present within their verified quote; otherwise that claim/relation is omitted. Candidate aliases still pass the resolver's body-evidence and collision checks; the caller's `alias_source` label is not trusted. Reprocessing reuses evidence, mentions, aliases and entity counts.
- **Cross-scope relation evidence:** A real PostgreSQL regression also found that a work-only relation could reuse the same global edge and attach work evidence to it. The edge uniqueness constraint is scope-independent, so persistence now skips evidence when the existing edge has a different derived visibility and increments `relations_scope_blocked`. This avoids changing a global edge; separate scoped copies need a future schema change.
- **Collector HTML structure:** Collector extraction previously handed trafilatura plain text to the envelope, losing DOM heading levels before delivery. HTML extraction now maps a heading to the next exact, retained paragraph/list/pre text and inserts a Markdown heading at that text location. Same-position nested headings preserve order. The parser version is `+parse-2`. The envelope and delivered source metadata carry raw handle/hash, normalized-text hash, parser/normalizer/chunker versions, normalizer steps, and the heading transform name. `DefaultParsingProcessor` continues to parse the already-normalized body as Markdown structure; it does not parse that text as raw HTML. Legacy `trafilatura-*+parse-1` revisions are held with `collector_html_structure_revision_required` instead of claiming headings were recovered from a flattened body.
