# KB v3 검색·접근정책 구현 — 2026-10-25

## 범위와 기준점

통합 작업 브랜치 `kb-v3/search-20261025`, 기준 커밋 `4ca1ed0d7f8471a3b73def4d9b8c5d7bd4d3cdec`. 원본 통합 worktree와 병렬 canonical/graph 구현은 수정하지 않았다. KB3-401/403 검색 구현 및 KB3-103 공통 접근정책 기반만 다룬다. 마이그레이션/데이터 백필, API/MCP 라우터 변경, main merge/push/deploy는 하지 않는다.

## 구현

- `kb_access.py`: owner/work-agent/personal-agent 권한 컨텍스트와 문서·passage·entity·alias·assertion·relation 필터. alias는 alias 테이블 문자열만 믿지 않고 권한이 있는 원문 passage에서 실제 출현을 확인한다.
- `kb_ontology/retrieval.py`: 이름/별칭 후보, entity passage, 증거가 연결된 1-hop relation, 정본 카드 검색. JSON에 저장된 정본 source/evidence ID는 허용된 문서·passage 계보와 대조해 걸러낸다.
- `has_open_conflict`도 정본 JSON flag를 그대로 쓰지 않고, 열려 있는 conflict의 양쪽 assertion이 모두 접근 가능한 원문 근거를 가질 때만 true로 반환한다.
- `kb_retrieval.py`: lexical/vector/entity/graph 후보 생성, RRF와 결정적 정렬·문서 다양성 감점, offset/has_more, source/type/domain/time/concept/current/status 필터.
- assertion 조회의 누락된 evidence-map join과 잘못된 `KbAssertion.object_literal`(모델에는 `object_value`)을 바로잡았다. hybrid 검색에서 vector 임베딩 실패를 삼키던 동작은 제거했다.
- 실제 PostgreSQL 실행에서 추가로 발견한 잘못된 assertion FROM/join을 수정했다. 개인 검색이 work-only 원문에서만 나온 별칭을 노출하지 않는 회귀 시험을 추가했다.
- 검색 함수 계약: `search(db, *, query, limit=10, offset=0, document_id=None, current_only=True, scope="personal", access_context=None, filters=None, mode="hybrid")`. 신규 API는 JWT/agent pool 등 신뢰된 caller에서 `create_owner_context` / `create_work_agent_context` / `create_personal_agent_context`를 만들어 `access_context`로 넘긴다. 사용자 입력의 `scope="all"`을 권한으로 사용하지 않는다. 기존 `scope` wrapper는 기존 `personal`/`work` 보안 경계를 유지한다.

PostgreSQL 제품 검색 시험은 lexical+hash-vector, alias, 1-hop evidence relation, canonical provenance, source type/time 필터를 실행했다. work-only `Polaris` 별칭은 personal query 결과에 나오지 않았다. hash embedding은 실제 pgvector SQL 배선 확인이며 E5 의미검색 품질 증거가 아니다. 실제 E5 실행/가용성은 미확인이고 Recall@5/MRR/latency 제품 검색 비교도 아직 측정하지 않았다.
