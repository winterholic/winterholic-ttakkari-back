# KB3-302 정본·충돌·그래프 작업 기록

- 날짜: 2026-10-25
- 작업 브랜치: `kb-v3/canonicals-20261025`
- 시작 스냅샷: `4ca1ed0d7f8471a3b73def4d9b8c5d7bd4d3cdec`
- 범위: 해당 스냅샷의 독립 worktree `back-kb-v3-canonicals`에서 정본 합성, 충돌 감지/해결, 그래프 질의와 canonicalizing 파이프라인 단계만 수정. integration 원본 및 API·모델·마이그레이션은 수정하지 않음.

## 구현

- `kb_ontology/canonicals.py`: Assertion→Evidence→Passage→Revision 실제 연결, owner 문서 접근·hidden/current 리비전·visibility 검증, 인용 없는 주장은 정본에서 제외. 정의 assertion이 없으면 증거가 확인되지 않은 `entity.summary`를 canonical definition으로 승격하지 않는다. key fact마다 assertion/evidence/document ID를 둔다. 기존 정본 내용이 바뀔 때만 version을 증가시키고, 반복 입력은 같은 내용으로 유지한다. `supersedes_id`/낮은 `rev_no` 과거 assertion은 파생 status만 바꾸며 원장 행은 수정하지 않는다.
- `kb_ontology/conflicts.py`: 활성/기존 disputed assertion에서 실제 supporting evidence와 현재 리비전 연결을 확인한다. 같은 predicate라도 `applies_condition`, modality, 유효기간이 호환되지 않으면 충돌을 만들지 않는다. 기간은 `[valid_from, valid_to)` 구간이 겹칠 때만 비교한다. 혼합 global/work_only 충돌에서 global assertion 상태는 보존하고 충돌은 work_only로 제한한다. `resolve_conflict`는 `resolved_a`, `resolved_b`, `resolved_both_valid`, `merged`, `kept_separate`를 처리하며 tenant/visibility/문서 접근/hidden/current/evidence 권한을 다시 검사한다.
- `kb_ontology/graph_query.py`: 허브·노드 카운트는 owner 접근이 있고 숨김이 아니며 현재 revision의 실제 evidence를 가진 `kb_document_entities`에서 계산한다. 1-hop은 증거를 가진 관계만 이웃 수 및 페이지 경계 계산에 포함하고 인용은 실제 evidence span에서 만든다. 대표 인용과 edge weight도 현재 호출자가 볼 수 있는 근거에서만 만든다. 원문 정본(summary)은 근거가 있는 canonical definition만 출력한다. graph/conflict list 페이지는 `offset >= 0`, `1 <= limit <= 100`이며 알 수 없는 visibility는 거부한다.
- `kb_pipeline/canonicalizing_processor.py` 및 adapters: 입력 revision의 문서 엔터티·주장 subject/object만 증분 처리하고 supersede projection, 충돌, 정본 갱신을 `ctx.fenced_session()`에서 수행한다. registry는 실제 processor를 반환한다. 외부 LLM 호출 없음.
- 테스트 helper는 현재 KbSource/KbPassage/KbEvidence 모델 컬럼에 맞추고 SQLite 배열 바인딩을 격리 변환한다. 테스트 데이터베이스를 SQLite 메모리로 한정한다.

## 서비스 계약

- `resolve_conflict(db, conflict_id, resolution, *, resolution_note=None, resolved_by=None, tenant_id="personal", caller_visibility="global") -> KbConflict`; 허용 resolution 외 값이나 접근 불가/없는 충돌은 `ValueError`.
- `list_conflicts(db, *, entity_id=None, status="open", caller_visibility="global", tenant_id="personal", offset=0, limit=50) -> list[KbConflict]`; `limit` 상한은 100.
- `get_ontology_hubs(db, *, tenant_id="personal", caller_visibility="global", entity_kind=None, domain=None, offset=0, limit=20) -> GraphHubsResult`; `to_dict()`는 nodes/total/offset/limit/truncated를 반환.
- `query_1hop_subgraph(db, center_entity_id, *, tenant_id="personal", caller_visibility="global", offset=0, limit=50) -> GraphQueryResult`; `to_dict()`는 center/nodes/edges/total_neighbors/offset/limit/truncated 및 원문 evidence refs를 반환.

## 남은 검토 항목

- 독립 검증 전이므로 PMS 상태는 `review`로만 이동하고 `done` 처리하지 않는다.
- 현 모델의 `uq_kb_entities_norm` 키는 `(tenant_id, visibility, entity_kind, norm_name)`이고 `domain`은 포함하지 않는다. 같은 이름·kind를 서로 다른 domain의 별도 모호 후보로 생성할 수 없다는 모델 경계가 확인됐다. 이번 책임 파일 범위를 벗어나 모델/마이그레이션을 바꾸지 않았으며, resolver가 이 형태의 후보를 만들 수 있는지 리드가 후속 결정해야 한다.
- 실제 PostgreSQL 통합 검증과 타입체크 실행 도구 가용성은 독립 검증자가 확인해야 한다.
