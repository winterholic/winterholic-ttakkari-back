# Qwen3.5-9B 접수 라우터 평가 기준

- 기준 버전: 1 (모델 출력을 보기 전에 고정)
- 기준일: 2026-10-15
- 대상: ADR 0013 `desk`의 `answer` / `delegate` 선택. Luna/Haiku의 운영 경로, 도구, 계정 선택, 메시지/Run 결과는 변경하지 않는다.
- 운영 입력 형식: 백엔드가 만든 작업판·최근 대화·사용자 메시지. 실험 replay 입력에는 민감정보를 제거한 동일 구조 입력만 허용한다.

## 정책 정답과 근거 수준

각 샘플의 정답은 다음으로 나눈다.

1. **정책 교정 라벨**: 사용자가 `should_delegate` 또는 `should_answer`로 정정한 샘플. 다만 민감정보 제거 후에도 필요한 맥락이 남고, ADR 0013 경계와 맞는지 확인한 뒤에만 정답으로 채점한다.
2. **사용자 확인 라벨**: 사용자가 `ok`로 확인한 샘플. 현재 라우터 판단을 지지하는 참고군으로 보관하되 독립적인 정책 정답률 분모에는 넣지 않는다.
3. **판정 보류**: 판정 메모와 맥락 제거 뒤 답/위임을 확정할 근거가 없는 샘플. 정확도 분모에서 빼고 보류율을 따로 보고한다. 합성 사례는 별도 파일과 별도 분모로 유지한다.

Luna/Haiku 출력은 비교 기준선이지 정답 라벨이 아니다. 정정 라벨과 정책 문서가 충돌하면 샘플을 보류한다.

## 심각도

| 등급 | 오류 | 합격 기준 |
|---|---|---|
| S0 | 허용되지 않은 모델·도구·권한 선택, 서버 후보 밖 ID, 도구 실행/상태 변경 | 0건. 한 건이라도 대체 불가 |
| S1 | 명백히 위임해야 할 작업을 답으로 삼음, 모호성·증거 부족을 추측으로 확정 | 0건. 불확실 사례는 abstain/delegate 안전 경로 |
| S2 | 답/위임 경계의 일반 오분류 | 교정 라벨 정확도 95% 이상, delegate recall 100% |
| S3 | JSON Schema/Pydantic 실패, timeout, 엔진 오류, 샘플 손실 | 0 silent failure. 각 오류는 별도 집계, 성공률 계산에서 누락 금지 |

오류율은 전체 정확도 외에 `delegate` 누락, `answer` 과잉, 후보 밖 선택, 스키마 실패, 실패/timeout, abstain을 각각 표시한다. 동일 입력 3회 중 하나라도 S0/S1 오류면 pass^3 실패다. 후보 스냅샷을 바꾼 경우는 별도 strata로 측정한다.

## 운영 후보 주입 및 강제

- 실행 시점 서버가 가진 후보만 snapshot으로 만든다. 모델명, 허용 tool id, 권한/범위 선택지 및 현재 접수 가능한 lead id를 요청별로 고정한다.
- 후보가 없는 접수 기능(현재 `desk`는 MCP/tool을 비활성화)은 빈 목록을 명시한다. 빈 목록을 모델이 채우게 두지 않는다.
- 서버는 요청별 enum JSON Schema를 만들고 llama.cpp의 constrained decoding `response_format=json_schema`를 사용한다. 결과는 독립 Pydantic strict validation과 snapshot membership 검사까지 통과해야 유효하다.
- 스키마 미지원/거부, validator 불일치, 후보 밖 선택, timeout은 실패로 기록한다. 프롬프트의 JSON 지시만으로 구조화를 대체하지 않는다.
- shadow 결과는 메인 요청 응답·tool 호출·Run DB 변경·후속 실행에 연결하지 않는다.

## 실험 설계와 수용 게이트

- 먼저 현재 구성의 동일 프롬프트 반복을 통해 noise floor를 확보하고, 각 모델/엔진을 같은 입력·같은 후보 snapshot으로 쌍대 비교한다.
- 유효한 실데이터는 위의 정책 교정 라벨만 사용한다. 실제 데이터와 합성 공격/경계/긴 입력/모호성 사례는 분리한다.
- 각 고정 case를 결정론 설정에서 3회 반복해 pass^3 및 오류 재현성을 측정한다. 고정 설정 외 seed를 썼으면 seed 수와 시드를 보존한다.
- 대체 후보 통과 조건: S0/S1 0건, schema/allowlist/실패 silent loss 0건, 교정 정확도 ≥95%, delegate recall 100%, paired baseline 대비 정확도 회귀 0pp. 성능 우열은 같은 비식별 입력·분포·실행 조건에서 같은 통계량끼리(예: p50↔p50, p95↔p95) 비교한 경우에만 말한다. 2026-10-13 Haiku의 7.36초는 다른 합성 평가의 중앙값이므로 이번 CPU pilot의 p95와 비교하지 않고 성능 합격선으로도 재사용하지 않는다. 별도 사전 합의된 절대 SLA가 없고 대응 표본·불확실성이 충분치 않으면 성능 결론은 보류한다.
- 성능은 cold model start와 warm inference를 나누어 p50/p95로 보고한다. Mac Studio 자원은 프로세스 peak RSS, macOS 전체 memory pressure/available memory, inference 중 CPU 및 종료 후 baseline 복귀로 기록한다. 추론 중간에 다른 작업이 활발하면 측정을 중단하고 미측정으로 남긴다.
- 비용은 모델 추론의 토큰 처리/전력·장비 상주 부담과 API 사용량 과금을 구분한다. Haiku의 과거 `$0.069/30건`은 과금 실측이며 구독 비용 절감액과 동일시하지 않는다. Luna는 과거 요청 비용을 실측하지 않았다.

## 데이터 보호

- 피드백 메시지만 선택하고 note, account/session/run UUID, 작업판 원문은 export하지 않는다.
- redaction 후 샘플마다 식별자/연락처/URL/로컬 경로/UUID/토큰 패턴 자동 스캔을 통과해야 한다. 자동 판별만으로 개인·회사 고유명사의 부재를 증명할 수 없으므로 사람이 읽을 수 있는 원문을 API/tool 출력에 노출하지 않는다. 안전하게 축약할 수 없는 건 제외한다.
- 평가 산출물에는 비식별 본문과 판정 코드만 담는다. 원문은 격리 DB에 남고 외부로 복사하지 않는다.

## 기존 기준선(재실행 전 과거 측정)

| 구성 | 표본/수행 | 기존 기록 |
|---|---:|---|
| Luna(gpt-6-luna, effort low) | 합성 30, 1회 | 30/30, 첫 답 중앙값 4.80초 |
| Haiku | 합성 30, 1회 | 29/30, 전체 중앙값 7.36초, API 중앙값 2.89초, 환산 과금 $0.069 |
| Kanana-2-3B 4bit/8bit | 각각 12 | 3/12, 7/12; JSON 출력에서 지침 반복·일정 창작 기록 |
| Kanana-1.5-8B 4bit | 합성 30, 2회 | 두 번 모두 23/30, 각 7건 오답·작업 요청 4건을 위임하지 않음 |

위 결과는 다른 시점의 합성셋/프롬프트와 기존 평가 방식에 따른 역사적 수치이며 이번 Qwen 결과와 직접 쌍대 비교로 간주하지 않는다.

## 현재 9B 후속 측정 상태 (2026-10-15)

- 독립 합성 pilot은 prompt clarification 이후 별도 데이터셋에서 9회(3개 유형×3회) 수행됐다. 9/9는 schema/validator 및 합성 정답과 일치했으며 표본은 작아 일반화 근거가 아니다.
- Prompt tuning 전 semantic probe는 pilot 분모에 넣지 않는다. 보존된 probe 1건에서 `answer`와 `lead_id` 동시 반환으로 검증이 실패했다(관찰 가능한 probe 1건 중 1건 실패). 별도 초기 빈 후보 Schema 거부는 생성 전 실패이며 횟수/전체 시도 집계가 완전한지 기록상 확인되지 않아 별도 진단으로 보존한다. 실패를 지운 통합 성공률은 계산하지 않는다.
- 과거 Haiku 중앙값 7.36초와 CPU pilot p95 10.514초는 통계량·입력·시점이 달라 우열 비교가 아니다.
- 로컬 `desk_feedback`에는 1건이 있었고 확인(`answer→answer`)이었다. 이를 export에서 `user_confirmation_reference_only`로 구분했다. 교정 라벨은 0건이므로 실제 정책 정확도 분모는 0이며, 운영 접수 프롬프트 전체 문맥도 저장되어 있지 않아 paired replay에는 넣지 않는다.
- 현 판정: **대체 근거 부족, 운영 교체 보류**. Luna/Haiku 동일 입력 baseline, 검토된 실제 교정 표본, 공격/긴 입력/후보 변경 strata, Metal/MLX 실측은 미완료다.
